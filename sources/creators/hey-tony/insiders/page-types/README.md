# HeyTony Page Types: research index

Everything Matt Diamante ("Tony", HeyTony) teaches about building each type of page on a website, one file per page type: what belongs on it, how it is structured and laid out, how it should be designed, what visuals to use, how long it should be, how the keyword is placed, what not to do, and the live examples from his coaching calls. Built 2026-08-21 from HeyTony sources only.

## Start here

1. Read `00-rules-for-every-page.md` once. It is the spec every page inherits: the five governing rules, the element-by-element page spec (title, meta, URL, headings, word count, density, readability, images, alt text, video, links, schema, speed, mobile, typography, color, spacing, accessibility, page builders, AEO, patience windows, auditing), a numbers table of every threshold, don'ts, and where Matt's own sources disagree.
2. Open the file for the page you are building (01 to 14). Every page file uses the same sub-headings, so page types compare side by side: what it targets, what goes on it top to bottom, layout and design, visuals, length and keyword density and on-page SEO, CTAs and conversion, links and site placement, don'ts, live examples from the calls, and where the sources are thin or disagree.
3. `15-what-the-emails-add.md` is the short version of the email tips; `heytony-email-tips.md` is the full dated digest with every prompt and checklist verbatim.

**The five rules that override everything:** one keyword per page, always; never touch a page that already ranks #1 to #3; match what is currently ranking for that keyword, never a fixed number; do not chase 100% on any audit tool; on-page content is the #1 lever, so fix the thin page before adding pages, channels, or tools.

## Honest limits

Matt's material is deep on homepage, service/money, location, ecommerce, blog, FAQ, and contact pages, and thin on legal, pricing, portfolio, and testimonial pages; each file says plainly where he has little to say. Where his sources disagree (accordion FAQs, schema, word-count floors, homepage title order, how unique a location page must be), both positions are recorded with citations rather than resolved. Em/en-dash-free per workspace rule.
