## Tactics & step-by-step how-to

- **GSC — find what a specific page ranks for:** Search Console → Performance → Search Results report → click **"+ Add Filter"** → select **Page** → paste the exact URL → Apply. Filters all queries down to just that page, showing what people actually search to land on it.
- **GSC — Discover vs Performance:** Discover tab = vague "opportunities"/general ways people find the site; Performance → Search Results = the Queries/Page/Countries/Devices breakdown you actually use to diagnose one page.
- **GSC — sitemap-lag check:** left sidebar → **Indexing → Sitemaps** tab shows the date Google last crawled your sitemap. If a redirect tests fine but GSC still shows "not found," check this date first — if it was scanned same-day, treat it as a Google-side lag, not a broken redirect.
- **Semrush — find what keyword a page ranks for:** paste the page/domain URL into the top search bar → view Authority Score + historical traffic graph → scroll to **Organic Research** section → **Top organic keyword** field shows the primary term driving that page.
- **Diagnosing a mystery/unexpected keyword ranking** (e.g. ranking for a service you don't emphasize): run the page through GSC or Semrush to find the exact page + query driving it, then decide whether to consolidate all related content onto one dedicated page or just re-optimize whichever page is already converting.
- **Live on-page heading cleanup pass** (homepage audit): go through the page and reclassify anything styled as a heading tag (H2/H3) or a button/title-tag that isn't really a heading — stat callouts, trust badges, list items — down to plain paragraph text with a larger font size instead. Use a page-audit browser extension to see the real tag structure.
- **Keyword-into-heading rewrite tactic:** fold the exact target keyword more directly into an existing H2, e.g. turning "You're trusted Med Spa experts in Scottsdale" toward "You're trusted Med Spa Scottsdale experts."
- **Cross-border guest-blogging workflow:** write one blog post in English on your own site, then offer it to a partner/sister company's site to translate and publish in their language, with a backlink back to your site. No volume cap — do as many as capacity allows.
- **Deciding whether to touch an already-ranking page:** for a full content overhaul, do partial variations only, don't rewrite all the content; purely additive changes (e.g. adding client testimonials) are always safe and won't affect rankings.
- **Portal/knowledge-base migration decision:** if a support/knowledge-base section must move off the main domain, keep it on a **subdomain** rather than a brand-new separate domain wherever technically possible. If the content is purely customer/support-facing (not acquisition content), it's fine to deprioritize its indexing entirely and focus effort on keeping the acquisition-facing blog indexed instead.
- **Google Business Profile cadence:** post **twice a week** (Hey Tony's own standard, applied to all clients + themselves). For photos, batch roughly **10 images**, then leave a gap of **a week to a month** before adding another ~10 — steady incremental additions, not one-time dumps.
- **Cross-platform local descriptions** (GBP + social via a GoHighLevel auto-poster): safe to reuse the same content/description across Google Business Profile, LinkedIn, TikTok, YouTube etc., as long as the local keyword stays consistent and it ties back to the website.

## Rules / dos & don'ts (keep every threshold, number, specific)

- Use **Request Indexing** only on priority/key pages — it bumps them up Google's crawl queue. Don't repeatedly hit "Start Validation"/"Validate Fix" on the sitemap — "I'll leave that alone," no benefit to mashing it.
- Large sites index **very, very slowly** — a rising indexed-page count over time is itself the success signal; no fixed timeline given.
- A chunk of "not indexed" pages on a large e-commerce/CMS site can simply be tag or category pages that were never meant to be indexed — not automatically a problem.
- After confirming a redirect works and the sitemap has been (re)crawled: wait **about a week or two** (Elliot settles on **"I'd say a week"**) before treating a lingering "not found" as a real issue — treat it as Google-side lag, not a broken redirect.
- Changing a page that's already ranking well: don't rewrite the *entire* page — that risks the ranking. Partial edits/additions only.
- Never move acquisition-facing content (blog) to a brand-new domain — Google treats a new URL as an entirely new domain, resetting the accumulated posting history, repetition, and indexed traffic built on the old one. Use a subdomain instead if a split is unavoidable.
- Purely internal/customer-support content (login help, billing, ticket knowledge base) doesn't need to be indexed — not worth spending SEO effort protecting.
- Blog/SEO priority order: **optimize converting service pages first**, then invest in ongoing blog content.
- Keyword-form consistency: if a keyword has two commonly-searched forms (e.g. "Med Spa" vs "Medspa"), pick **one** and use it consistently across H1, title, meta description, and H2s; use the variant only in body copy, not in structural tags.
- Removing an outdated pricing/package list from a page (e.g. switching pricing systems, don't want exact numbers public) is safe and won't hurt rankings — confirmed explicitly as low-risk.
- Guest/partner blogging: no penalty for publishing a lot, no penalty (positive or negative) for publishing none — it's a **net positive** because it's a backlink and spreads domain authority over time.
- Exact-match keyword in the title tag/meta description is allowed to read less naturally than normal copy: "the title and description are okay to... push the boundaries of that a bit more."
- On-page exact-keyword usage found only **once** on an otherwise-strong homepage was flagged as a clear, easy opportunity to add more instances/variations.

## Tradeoffs & nuance

- Ranking for a keyword you weren't targeting (e.g. headshots) isn't automatically bad — the default move is to consolidate/optimize toward it if you genuinely offer that service, not suppress it, since removing it outright risks losing a working lead source.
- Two pages competing for the same keyword is framed as generally undesirable ("ideally they should be different"), but treated as a non-issue when the shared keyword is a branded term rather than a commercial one — the same cannibalization signal reads differently depending on keyword type.
- Blog content "doesn't always convert" — value depends on how competitive/high-intent the targeted keyword is — but is still worth doing regardless of direct conversion because its real job is making the site indexable/findable and building topical authority.
- Elliot explicitly flagged the limits of his own certainty twice: deferring conflict-finder tool errors to Matt (who built it) and deferring the "should social captions differ per platform" question to Matt (the team's social specialist) rather than guessing.
- Splitting off a support portal is a genuine technical-vs-SEO tradeoff: Jason's underlying problem (can't keep WordPress updated because of the old bolted-on system) pushes toward separating platforms, while the SEO risk pushes toward keeping everything on one domain — resolved only because the portal content itself turned out to be low-value from an acquisition-SEO standpoint.
- Keyword-form indecision ("Med Spa" vs "Medspa") isn't wrong to have both forms present — both were being searched — but consistency in the primary structural tags (H1/title/meta/H2) matters more than which of the two valid forms you pick.
