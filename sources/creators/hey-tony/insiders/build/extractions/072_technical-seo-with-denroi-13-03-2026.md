## Tactics & step-by-step how-to

- **Finding the XML sitemap in Yoast:** Yoast SEO > Settings > scroll to the bottom of the page > "XML sitemaps" section > click "View the XML sitemap" to see the auto-generated sitemap. (Rank Math, by contrast, surfaces a directly copyable sitemap link — easier to hand off than Yoast's.)
- **Yoast schema toggle:** turning it on auto-generates standard/generic schema across every page type (blog posts, regular pages, service pages, homepage) with zero extra setup. For anything more specific — reviews, prices, FAQ blocks — you need a third-party plugin/tool on top.
- **Optional Yoast → Google Site Kit connection:** skip it as long as you can already confirm tracking works directly inside Google Search Console and Google Analytics.
- **WooCommerce product description showing in the backend but not on the live page** — diagnostic + fix sequence:
  1. Get the live URL and check robots.txt first (a disallow rule, or a JS rendering failure, can make an audit tool report "no text found" even when text exists).
  2. In WP admin: Appearance > Theme Editor (or File Editor) > find the product template file (naming varies — "product JSON," a "single product" file, or `product.php`).
  3. Search that file for the "description" class. There should be two blocks: the base/default description and a separate WooCommerce description.
  4. If the WooCommerce description block is missing from the template, use ChatGPT to write that WooCommerce description code, then paste it into the product PHP file.
- **Deciding between two nearby local keyword markets** (business physically in Portland, OR but ~5 minutes from Beaverton, where most real customers are): don't guess — set up Google Search Console first, then check which term real search traffic is actually using before touching page copy. Rule given: if 50% or more of queries use one location's name over the other, optimize the page around that one.
- **H1 rewrite process (demoed live):** open the page, identify the current H1 if it's a long stuffed phrase repeating the keyword, keep only the target keyword phrase as the H1, and move the rest of that sentence down into an H2 or plain paragraph text. If you liked how the longer version looked, restyle the new shorter H1 with CSS to match the old visual.
- **Subheading keyword pass:** scan every subheading on a page for a natural spot to reinsert the local/target keyword — e.g., "Camp Schedule and Camp Themes" → "Beaverton Camp Schedule and Camp Themes."
- **CTA button copy pass:** replace every generic "Learn More" with copy naming exactly what it leads to, keyword included — e.g., "Learn more about Design Art Camp," "Learn more about Squishmallow Art Camp."
- **Diagnosing slow/animated sections as a crawl risk:** reload the page and watch how long content takes to visually appear. Google's crawl bot loads the page and effectively "scrolls" through at a set pace — if content hasn't rendered by the time it passes that point, it may not register. Fix: go into CSS/animation settings and cut section-reveal timing roughly in half. On Squarespace specifically: in the page editor, drag the small resize handle in the corner of each section upward to shrink the dead/empty space before content displays.
- **Blog-to-service internal linking play:** instead of one page trying to cover many camps/services at once, write one blog per specific camp/service so each can hyper-focus on a single keyword and talk up the benefits, then internal-link from that blog straight to the matching signup/service page.
- **Multi-location page keyword-saturation pass** (pest control example): audit every heading on a location page, not just the H1 — rewrite each generic one to include the location name: "Why choose [Brand]" → "Why choose us for pest control in [Location]"; "Kind words from our customers" → "Kind words from our customers in [Location]"; "Learn more about spider control" → "Learn more about spider control in [Location]."
- **Diagnosing site-wide click failures** (e.g., a cookie-consent "Accept all cookies" button that isn't clickable): treat as a JS/plugin conflict — check GDPR, accessibility, and chat-widget plugins as likely culprits; also check for geo-IP/country-blocking plugins if you're testing from a different country than the site serves (the bug can be intermittent — it resolved on a reload during the call).
- **Anchor text specificity pass on existing blog posts:** find any anchor that's a single vague word (e.g., just "most" inside "one of the most common questions") and expand the linked text to describe the destination page (e.g., link the full phrase "most common questions about pest control" when linking to a pest control FAQ page). Also shorten anchor text that's an entire long sentence down to a short, destination-specific phrase (e.g., a long sentence about "pests active in the summer in Florida" → "pests in the summer").
- **Internal-link audit for old blog posts:** confirm every post links to at least one location or service page (not only to other blog posts), and reposition/add those links higher up in the post rather than only near the bottom.
- **Robots.txt check process:** WordPress + Yoast → Tools → File Editor → open `robots.txt`. Look for `disallow` lines — those indicate what's blocked. An untouched default file blocks nothing, so a ranking or audit-tool problem is coming from somewhere else (a plugin, JS, or the tool itself).
- **Handling a competitive head-term where the real top-3 SERP holders are non-competitor authorities** (airlines, in this case): still run the standard competitor-analysis exercise on positions 1–3 — you're analyzing for the ranking position, not for who currently holds it.
- **Building a single-intent "money page" landing page:** make the exact target keyword the H1 and the title, cover it again in the first H2, then build the body out with lists, tables, and explicit numbered steps. When you're up against big-name incumbents, use a comparison table to show yourself vs. them — without linking to them.
- **Niching down an overly competitive seed keyword:** in SEMrush, type the seed keyword in, open "Keyword Ideas," click "View all," then sort/scan by search volume while checking keyword difficulty for named-entity variants (pairing the seed term with a specific competitor/airline name) that carry real volume but much lower difficulty. Build one dedicated page per such variant.
- **Structuring navigation around many single-intent pages:** add each named entity (e.g., airline) as its own nav item or dropdown entry, each linking to a dedicated landing page built around that specific keyword variant, each with its own CTA funneling into the core conversion action (e.g., "start your claim against Porter Airlines").

## Rules / dos & don'ts

- Standard/generic schema via Yoast's toggle is essentially free — turn it on regardless of niche. Custom schema (reviews, pricing, FAQ) is optional, lower priority, and needs extra tooling.
- Schema is explicitly lower priority than content: "if you write good content, then that matters a lot more than just having a schema markup on the page." Framed as more important in the past, less so now.
- Set up Google Search Console **before** deciding which of two nearby local markets to target. Threshold given: optimize around whichever location term **50% or more** of real queries use.
- One H1 per page; the target keyword should appear once in it, not stuffed/repeated within the same tag.
- **"One keyword per page"** — stated as the general site-architecture rule, applied both to a single landing page's heading structure and to how an entire site's pages/nav should be organized.
- Never ship generic CTA copy ("Learn more") — it carries no keyword and gives no context on what "more" means.
- Anchor text must specifically describe the destination page — never a single vague word, and not an entire uncut sentence either.
- Every blog post must link to at least one location page or service page, not exclusively to other blog posts.
- All internal and external links carry SEO weight, but links placed higher up in the content carry slightly more than ones lower down.
- Don't fully trust ChatGPT for SEO heading structure or content architecture — fine for implementation tasks (e.g., writing missing WooCommerce PHP code), but "does make a lot of mistakes" on SEO specifically and tends to produce keyword-stuffed output.
- A default Yoast/WordPress robots.txt blocks nothing; only add `disallow` lines for things deliberately hidden from crawlers (admin dashboard, throwaway pages). If Search Console already shows traffic, leave it alone.
- Turn off geo-IP/country-filtering plugins, especially once you start publishing blog content meant to be crawled and found.
- Never link out to competitors — repeated explicitly for the flight-delay case ("never link to competitors, never link to those airlines"). Mentioning them by name or comparing them in a table is fine; hyperlinking is not.
- Homepage should almost never be treated as the primary "money page" — it's one landing page among many that SEO work will produce.
- Brand-new Insiders-community tools (Money Page Doctor, People Also Ask tool, Reddit Keywords tool) were all under one month old at call time — expect bugs and unresolved edge cases.

## Tradeoffs & nuance

- Schema markup is worth turning on since it's free via Yoast, but it shouldn't be chased at the expense of content quality — this is a priority ordering, not a binary choice.
- Nearby-market keyword targeting (Portland vs. Beaverton) has no default answer — it must be settled with real Search Console data, since a business's literal address doesn't necessarily match where its actual demand concentrates.
- Squarespace's animated section reveals create a direct tension between visual/artistic design and crawlability/perceived load speed — Google's crawler is described as effectively "scrolling" through a page at a fixed pace, so content that renders in after that pace risks not registering at all.
- ChatGPT is useful for implementation tasks (writing missing PHP code) but unreliable for SEO strategy/content architecture — on this call it introduced keyword stuffing into a client's H1 when asked to structure headings.
- Brand-new Insiders tools (Money Page Doctor, People Also Ask, Reddit Keywords) are still shaking out bugs — a failed audit result can stem from the tool itself, from the site's robots.txt, or from JS rendering, and it isn't always possible to pin down which live on a call.
- For an overly competitive seed keyword, the fix isn't to abandon it but to pair it with a narrower named entity (a specific airline) to find a winnable variant — same underlying demand, a less-contested entry point. Caveat given: this isn't a "local" keyword, so difficulty scores can skew by country, which matters for a company operating globally.
- When the real top-3 SERP holders are massive non-competitor authorities (airlines) rather than similarly-sized rivals, the standard competitor-research homework still applies unchanged — the target is the ranking position itself, not the entity currently holding it.
- Internal-link weighting is a matter of degree, not all-or-nothing — every link carries some value, but placement (higher on the page) carries more, which is why revisiting and repositioning links in old content is worth doing rather than only adding new links going forward.
- Local multi-location SEO isn't satisfied by creating the page — the location keyword has to be threaded through every heading on that page, not just the first one or two.
