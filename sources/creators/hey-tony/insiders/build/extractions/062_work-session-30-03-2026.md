## Tactics & step-by-step how-to

- **Blog topic sourcing, primary route**: go to answerthepublic.com → type in what you sell → scroll to the "Questions" section → click through to view all results (e.g. "view all 180 results") → go to page 3 or 4 of the list, where volume is lower — these are easier to rank for. Ranking for one long-tail question often also ranks you for related variations, so real traffic can exceed the volume shown for that single keyword.
- **Blog topic sourcing, alt routes**: (1) HeyTonyInsiders app → Tools → "Blog Idea Finder" — type in what you sell (e.g. "Hot Sauce") → returns questions; (2) HeyTonyInsiders → Insiders section → scroll down → "Blog Topic Finder" — backup if the app tool won't load or you can't log in; (3) "Reddit Keywords" tool — type in what you sell → searches Reddit for that term and surfaces real questions people are asking there.
- **Writing the post**: take the chosen question into Claude (works in ChatGPT/Grok too) → paste the question → prompt it to ask you clarifying questions first, pulling on your own expertise/experience/case studies/opinions, before drafting. Reconstructed prompt language: *"[I'm] writing a blog post, answering this question [paste question]... ask me 10 questions [you need to know], use my expertise, experiences, case studies, opinions, etc."*
- Optional: answer the AI's clarifying questions via voice mode on your phone rather than typing (one member's workflow) — desktop voice mode was reported as poor.
- Optional efficiency step: save the above as a standing Claude "Project" with a fixed prompt template (e.g. always requesting H1 tag, H2 tags, and meta description as outputs) so you don't retype instructions each time. Not mandated — do it only if it removes friction for you.
- **Orphan-page triage**: pull a full backlink report (e.g. in Semrush) → download all backlinks → cross-check which orphan pages actually have a backlink pointing at them → for each one, ask "is this page rank-worthy, do I want it to rank for something?" → if yes, add an internal link to it from any page a human can reach (doesn't have to be the homepage); if no, leave it alone.
- **Fixing a duplicate-H1 popup issue**: open the popup element → change its heading tag to plain paragraph text → restyle it to look visually identical so nothing changes for the visitor, only the underlying markup.
- **Finding citation/backlink targets for a non-local ecommerce brand**: pick a competitor → pull their backlink profile with a tool → get listed on the same directories/sites they're already listed in ("they've already done the work for you to find all those").
- **Redirect decision**: replacing a page's content with new/updated content (even under a new URL) → set a 301 redirect from old URL to new; keep the new content topically related to what the old URL covered. Deleting content with nothing to replace it → let the old URL 404, don't redirect it.
- **Adding a keyword to an underperforming category page without touching the original**: don't rename or replace the broad page; build a separate, new page/collection targeting the specific keyword variant instead (example given: keep the general "Necklaces" page, add a new "Murano Necklaces" collection page, and link to it), so the original page still covers the broader category.

## Rules / dos & don'ts

- Content cadence: Matt's default recommendation is **1–2 blog posts per week**. Higher cadence is fine only if quality holds — forcing a schedule risks publishing weaker posts just to hit the number, and risks running out of good topics.
- Answer The Public's listed search volumes are estimates, not reliable numbers, and are geography-scoped (defaults to whatever country is set) — don't chase a keyword purely because its listed volume looks high, and don't skip a low-volume one either, since variant traffic often exceeds the single-term number shown.
- **"Best X" / comparison content rule**: if people search things like "best LinkedIn courses" and answering means listing competitors, don't publish that piece on your own site unless you can place yourself somewhere on the list. A "best of" list that omits your own brand actively signals to Google/AI that you're not a contender. If you don't want to name competitors or yourself, get the piece placed on a third-party site instead.
- Orphan pages are **not inherently bad for SEO** — fine to have them; Matt keeps many on his own site (e.g. Rank Week pages, Insiders pages). Only worth fixing the ones that are backlink-worthy or should be ranking.
- Keep lead-magnet/ebook orphan pages regardless of backlink status — they still drive the business through email capture.
- Every page needs exactly one H1 — it tells Google what the page is about; missing or duplicate H1s both hurt.
- **URL/slug change rule — check all three before touching a URL**: (1) is it ranking? (2) does it get traffic? (3) does it have backlinks? Only change the URL if all three come back negative.
- Changing even a single character in a URL makes it an entirely new URL to Google: it has to be re-indexed, any existing rankings for the old URL may not carry over, and any backlinks to the old URL become void unless redirected.
- If you do change a URL, you must go through the whole site and update every internal link that pointed at the old URL.
- Homepage URL should just be the bare domain — that's already correct, don't try to "optimize" it further.
- Local-only directories (e.g. Yellow Pages) are for businesses with a real local/physical presence or local service area — skip them if you have no physical store, even if you ship broadly (e.g., across Canada and the US).
- BBB (Better Business Bureau): free to get a basic listing; paid tier only buys "accredited" status; you do not need to be a local business, just a business, to list.
- AI/LLM visibility: Matt has **not** seen schema markup or other commonly-cited "AI SEO" tactics move the needle much — consistently publishing good content is, in his view, the single biggest lever for showing up in AI answers.

- **Claude** — used for blog drafting; called out repeatedly across multiple members as noticeably better than ChatGPT at content writing. Matt's team uses a mix of ChatGPT and Claude internally but leans Claude for output quality. Claude's annual plan was noted as cheaper than paying month-to-month. ## Tradeoffs & nuance

- High publishing cadence (Todd's 5/week) can drive strong results, but Matt frames it explicitly as an exception tied to finishing a specific content "hub," not the recommended default (1–2/week) — the risk is quality erosion under a forced schedule and running out of good topics.
- Orphan pages are a genuine gray zone: not inherently harmful, but a backlink pointing at an un-linked orphan page is wasted ranking potential until it's internally linked — worth an occasional audit pass, not urgent cleanup.
- Search-volume numbers from tools like Answer The Public shouldn't be trusted as precise, but shouldn't be dismissed for looking low either — a "30/month" keyword can still be worth targeting because ranking for it often pulls in related variant traffic too.
- URL/slug optimization is a real tradeoff: better keyword match in a URL can help an underperforming page, but touching a URL on an already-ranking/backlinked/trafficked page risks losing existing equity — Matt's stance is conservative (leave it alone unless all three checks come back negative).
- Directory/citation building isn't universal: valuable for local/physical-presence businesses, low value for a nationally-shipped ecommerce brand with no storefront — the better move there is competitor backlink analysis instead of generic local directories.
- AI/LLM visibility take is presented as Matt's own observation, not a proven universal rule — he's explicit it's based on what he's personally seen make a difference (content) versus what he hasn't (schema markup, other tactics).
- Heavy Claude usage note: a self-described power user paying ~$250/month still hits usage limits, but Matt attributes this to heavy internal tool-building rather than typical usage — regular members on the standard ~$20–30/month tier aren't expected to hit those limits.
