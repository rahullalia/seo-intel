# Web Design for SEO — 13.05.2026 (Leanne Jones, Leanne Digital)

## Tactics & step-by-step how-to
- Live Figma workshop building the **contact page** for the recurring mock massage-therapy site (home, about, service pages, location pages, "who we serve," blog roll, blog post pages already built in prior sessions).
- Contact page checklist — must include: phone number, email, opening hours, socials, contact form, map/location.
- Put the contact form (or the highest-priority contact method) as close to the top/hero as possible — "above the fold" — so the visitor doesn't have to scroll. If phone calls are the real priority over form fills, put the phone number up top instead of the form.
- Hero/banner section of every interior page should stay visually cohesive with the rest of the site so visitors feel like they're "traveling on the same website."
- H1 rule for non-ranking pages: for a page you're not trying to rank (contact page), the H1 doesn't need the focus keyword — just label it plainly ("Contact Us"). For pages you ARE trying to rank, put the focus keyword in the H1 **and** in the first paragraph.
- Design-first workflow (Figma before building): wireframe first because (1) it surfaces bad ideas before you're fighting the live builder, and (2) it stops you from repeatedly uploading "maybe this image will work" test photos into the CMS media library, which bloats the site with unused large files.
- Testimonial box build steps (Figma, transferable to any builder): quotation-mark icon recolored to brand color → reviewer name (bolded, stands out from body text) → testimonial body text → star icons cloned via Option (duplicate) + Shift (align) keyboard shortcuts → star color set to gold/yellow (matches Google's star color) → add +1px corner radius to the stars/box so they read as friendlier, not "too pointy."
- Instead of live-embedding Google Maps, take a screenshot of the map, upload it as a static image, and make the whole image a link out to the real Google Maps listing — protects page speed. (Confirmed this is what Hey Tony's own site does.)
- Grid alignment: align every element to the design grid so nothing feels "floaty" or unanchored; most builders snap to a grid automatically.
- Trust builders to layer onto a contact/home page: testimonials, star ratings, association/accreditation logos, FAQs.
- FAQ placement rule: don't run a single generic FAQ page — distribute FAQs across every page, each set relevant to that specific page's topic (e.g., deep-tissue-massage FAQs live on the deep-tissue service page, not the generic homepage FAQ block).
- Lead-form volume/quality lever: add qualifying questions (e.g., "what's your budget?") to filter out unwanted leads when there are too many low-quality inquiries; remove questions (even drop the phone-number field) to raise completion volume when there aren't enough leads coming in.
- Homepage wireframe skeleton Leanne starts every build from: Hero (H1 + message + CTA) → trust-building elements (awards, agency associations, testimonials, "Rated 5 stars on Google" style badges) → further sections → FAQs (page-relevant) further down.
- Anchor-link CTA technique (platform-agnostic — works in Showit, Squarespace, WordPress, etc.): give a page section an ID (e.g., `id="contact"` in the builder's ID/Class field), then point a button/CTA's link at `#contact` (hashtag + ID name) so clicking it scrolls down to that section instead of loading a new page.
- Corner radius as a brand-personality dial: more rounded corners = friendlier/softer appeal (good for massage therapy, photography of babies); less/no radius = more serious appeal (good for cybersecurity/B2B-hard-tech branding). Applies uniformly to buttons, cards, boxes.
- Accessibility/contrast workflow: sample the actual background and text hex values, run them through a color-contrast-checking tool, and iterate — darker backgrounds (near-black, e.g. `#191919`) with white text reliably pass; midtone grays are the most likely to fail; test each color pairing independently (don't assume one that works elsewhere will work here).
- Diagnosing "why does my heading look different in the review vs. what the designer sees": check whether the platform (Squarespace, in this case) is sizing text in REM/percentage units rather than fixed pixels — inconsistent rendering across browsers/devices is a common symptom; fix by switching that font-size field to pixels.
- Platform-switch decision framework (asked when a client wonders whether to move off Showit to WordPress): ask (1) is the current site already ranking? if yes, stay put; (2) does the owner find the current platform easy to use? if yes, stay put — because WordPress's flexibility only helps if it doesn't also cause you to abandon consistent updates/blogging.

## Rules / dos & don'ts
- Contact page is NOT a page to chase rankings for — optimize it for conversion and findability, not keyword targeting.
- Do include phone, hours, socials, and a contact form near the top; do NOT bury the contact form below other content.
- Never put two contact forms on the same page (e.g., one in the page body plus one repeated in the footer) — one contact form per page, full stop. This holds even though some SEO advice suggests repeating contact forms/embedded maps helps rankings — for a page that isn't a ranking target anyway, it's redundant UX.
- Always use REAL reviews/testimonials in production — the fake reviews shown in the demo were explicitly ChatGPT-generated placeholders for illustration only.
- Keep heading tags semantically correct: don't let a stylized subheading get auto-tagged as an H1 by the builder — reclassify it to a div/span if it's not meant to be read by search engines as the page's main heading.
- The literal H1 doesn't have to be the biggest/flashiest line visually — you can style it smaller for design reasons, but it still has to exist in the code as an actual H1 tag with the right semantic content.
- Never repeat identical FAQ text verbatim across multiple pages — each page needs unique text; Google penalizes duplicated content across pages.
- Font choice (script vs. serif vs. sans-serif) doesn't matter for SEO — readability is what matters, and mixing font styles inside one line of text can accidentally break the line into two separate heading tags (avoid that).
- Platform choice (Showit, Squarespace, WordPress, etc.) doesn't matter to Google directly — any platform can rank. WordPress is popular with agencies/designers because it maximizes their flexibility to optimize, not because Google favors it.
- Delete unused images and hidden/unpublished pages from the CMS — they still exist as real files on the server and add bulk/weight to the site even when hidden from navigation.
- Avoid unnecessary plugins if they slow the site down — raw text + CSS is the fastest-loading combination; a testimonial plugin or embedded map/review widget is a common candidate to replace with static text/images if speed testing shows a problem.
- Contrast rule: avoid pure black text on pure white background (or vice versa) — it reads as visually "vibrating" and is harder to read; soften toward off-black instead.
- Stay in darker tonal ranges for background colors if reliable contrast-pass is the goal — midtones are the danger zone most likely to fail.
- Brand accent colors (e.g., gold/yellow) must be checked against EVERY background they'll appear on separately — gold generally fails contrast against white but passes against black; don't assume one passing combination generalizes.
- Real legal stakes: referenced an actual case where an attorney was defending a client sued over a website with insufficient contrast for visually impaired users — treat WCAG contrast as a compliance/liability issue, not just an aesthetic preference.
- Body copy sizing: don't let body text read tiny relative to headings — if increasing readability, jump to a concrete size like 18px rather than leaving it ambiguous.
- B2B vs. B2C doesn't change the underlying wireframe/section skeleton — it only changes branding execution (fonts, colors, corner radius, imagery). The same layout skeleton works for "basically most service-based businesses" regardless of B2B/B2C or industry seriousness.

## Tools, prompts & resources
- **Figma** — Leanne's design/wireframing tool of choice, used to mock up pages before building in any CMS/builder; explicitly not required (pencil-and-paper wireframing works too) — the point is planning before building, not the specific tool.
- **ChatGPT** — used live to generate placeholder/fake testimonial text for the demo mockup (explicitly NOT for production use — real reviews only in production).
- **Claude** — mentioned by attendee Ariel: she had Claude build out a dark-themed landing page/color scheme for an event promotion, which she was then considering (and ultimately advised against) porting into her main site's branding.
- **Google PageSpeed Insights** — recommended tool to test actual site speed impact whenever adding testimonial plugins, embedded Google review widgets, or embedded maps; link dropped in the call chat.
- **Color-contrast-checking tool** (unnamed website referenced live, "play around with this website... to help you pick out colors," pass/fail readout per hex-pair) plus a mention that a Chrome extension version of a contrast checker also exists.
- **Showit** — attendee Ariel's platform; discussed hidden-page bandwidth behavior and whether to migrate off it to WordPress.
- **Squarespace** — used by two reviewed sites (PureCollis.com and one other); discussed global/template-locked heading sizing and REM-vs-pixel font-size units.
- Anchor-link `id="section"` + `href="#section"` pattern — platform-agnostic technique for scroll-to-section CTAs, demoed live on one attendee's homepage.

## Tradeoffs & nuance
- Design-first (Figma) vs. build-first: not mandatory tooling — pencil-and-paper wireframing is an equally valid substitute. The real tradeoff being managed is bad-ideas-live-in-the-builder and media-library bloat from repeated trial-and-error image uploads, not any specific software requirement. If a site is already built and styled, skip straight to building new pages instead of wireframing from scratch.
- Contact-form placement is goal-dependent, not a fixed rule: form above the fold if form-fills are the priority; phone number above the fold instead if calls are the priority.
- Lead-form length is a volume/quality dial, not a fixed best practice: more qualifying questions raises lead quality but lowers volume; fewer questions (or dropping fields like phone number) raises volume but admits lower-quality leads — the right setting depends on which problem (too many bad leads vs. too few leads) the business actually has.
- Embedding real Google reviews via a plugin vs. pasting text is a speed-vs-perceived-authenticity tradeoff: plugin embeds are "verified live from Google" and still contribute word count, but risk page-speed cost; static pasted text is faster but loses the live-Google-sourced framing. Decide based on actual PageSpeed Insights results on that specific page, not a blanket rule — and note that for a page that isn't an SEO ranking target anyway (like the contact page), the SEO-credit argument for the plugin matters less.
- Platform-switch decisions shouldn't be driven purely by "which platform is theoretically best for SEO": if the current site already ranks, or the owner finds it easy to use, staying put usually wins, because abandoning consistent updates/blogging due to a steep new learning curve costs more than any platform's SEO ceiling.
- Duplicating contact forms/embedded maps across a page is sometimes recommended elsewhere as an SEO tactic (repetition/embed signals), but Leanne holds the line at one form per page regardless, since the contact page specifically isn't being optimized to rank in the first place.
- On-page anchor-scroll CTA vs. a dedicated contact page: presented as neither right nor wrong, just an alternate UX pattern — anchor-scroll skips a full page load (faster perceived experience, better for maximizing inquiry volume) vs. a separate page (more conventional, allows a fuller/different context around the form).
- B2B/B2C and industry tone (e.g., cybersecurity) should steer branding execution (sharper corners, less rounding, more serious color/type choices) but not the underlying wireframe/section skeleton, which Leanne says holds for "basically most service-based businesses" regardless of audience type.
- Accessibility/contrast sits at the intersection of aesthetics and legal liability (referenced lawsuit) — it isn't purely a stylistic call, which raises the bar above "does it look fine to me."
- Page/homepage length has no fixed "too long" ceiling — length is acceptable as long as it still serves both user experience and adequate SEO word count; a long e-commerce homepage (Huckberry) was cited as a cross-industry proof point rather than a direct template to copy.
