## Tactics & step-by-step how-to

- **Identifying an unknown site's CMS/platform:** paste the site URL into whatcms.org — instantly reports the platform (live example correctly identified "Adobe Dreamweaver" for a hand-coded HTML site).
- **Before agreeing to migrate a hand-coded site to WordPress:** ask the client what the current editing process is (e.g., do they FTP into a server?) to gauge how the site is maintained, then check existing SEO tools (Ubersuggest/SEMrush) plus Search Console/Analytics/Tag Manager to see if pages are actually ranking and getting traffic. If the site isn't ranking, an easy full move to WordPress is fine. If it is ranking and getting traffic, be very careful about how you move it — could take a lot of time on a site with years of published content. Focus effort on the pages that are actually ranking; ignore the likely large number of zero-traffic/zero-impression pages.
- **URL preservation during a CMS migration:** keep every URL exactly the same, including whether www is used or not (www vs non-www counts as a different URL to Google even if the slug is identical) — also carry over H1s/H2s into the new build.
- **Building location pages (service businesses):** write a separate page per city/service area since each city has different keyword difficulty and search volume (example given: "SEO Agency in Toronto" needs its own page distinct from "SEO Agency in Hamilton").
- **Location pages placement:** footer-only placement (no top-nav link) is fine — the only requirement is that the page is reachable by some click path from the homepage; unreachable pages are "orphaned" and need internal links built to them.
- **Expanding into cities you don't yet operate in:** still build the location page, but do keyword research first to confirm actual search volume exists for [keyword + city] — as a rule of thumb, higher city population usually means more likely to have search volume. Add the new city as a new column/section in the footer alongside existing service links.
- **Post-relaunch technical check (top priority):** after any redesign/relaunch, the first and most important thing to check is whether any URLs changed (including www/non-www). If yes, set up 301 redirects from every old URL to its corresponding new URL immediately.
- **Auditing GSC after a relaunch, in order:**
  1. Check Indexing → Pages report; a sudden drop in the number of indexed pages is a warning sign something's wrong.
  2. Open the "Not found (404)" bucket and manually click through each URL to confirm none are real content pages that need a redirect (harmless if they're just builder/template/category pages nobody wants ranking anyway).
  3. Open "Crawled – currently not indexed" and check whether those are real, wanted pages.
  4. Check the Sitemaps tab — if the sitemap is segmented into multiple files, submit each one individually; GSC won't automatically pull in all of them.
- **Fixing "Crawled – currently not indexed" pages:** build internal links to the page — sometimes needs 10-15 links, especially for pages targeting a very competitive keyword.
- **When a page targets too hard a keyword** (e.g., bare "SEO"): retarget the page copy/H1 toward an easier, more specific variant instead (examples given: "hire SEO expert in [city]," "hire SEO services," "free SEO audit," "free SEO analysis" — rejected a proposed alternative, "Discover your website's true SEO potential," as still far too hard/vague to realistically rank for).
- **On-page optimization pass (used live on a roofing "metal roofing" page), in order:** title tag → meta description (keyword position) → H1/H2 → body headline phrasing → CTA text → FAQ/accordion → comparison tables → internal-link section.
- **Meta description rewrite rule:** move the target keyword as early as possible in the string — weight from a keyword decreases the later it appears, and this applies to any search, not just this niche.
- **Fixing an over-optimized headline** (example: "Metal roofing is the last roof you'll ever need" — flagged as redundant/awkward repetition of "roof/roofing"): reword to something natural that still contains the location + service keyword, e.g. "Why a metal roof is important in Vancouver."
- **Padding thin sections to rank for more variants:** double or triple the length of short paragraphs while working in more location+service keyword variants; add a toggleable FAQ/accordion (examples generated live: "What is the most common roof color?", "Does roof color matter?", "Does roof color affect temperature?") to increase keyword density and topical coverage.
- **Add comparison tables** (e.g., your cost vs. a generic competitor's, or a table comparing roof colors and temperature) — called out as something that "always works fantastic for Google."
- **CTA rewrite rule:** replace every generic "Contact Us" button/link with descriptive anchor text tied to the service + location (e.g., "Contact a Vancouver roofer," "Contact a professional roofing company").
- **Bottom-of-page internal linking block:** on every location/service page, add a closing section (e.g., "Are you looking for other roofing services?") that lists every other service page with a one-line description and a link, connecting all service pages to each other.
- **Blog-to-service linking rule:** blog posts should always link to at least one service page. Service pages linking back to blog posts is optional; if done, the best spot is inside the FAQ section.
- **Adding a CID-linked address:** make the business address on the site a clickable link using the Google Business Profile's CID link (not the plain address text, not the standard GBP share link).
- **Getting your CID link — two methods:**
  1. Preferred: install the Plerdy WordPress plugin, which surfaces the CID number/link directly.
  2. Less preferred/manual: view page source on the GBP listing and search for "ludocid."
  Final usable link = Google Maps URL + `?cid=[number]`.
- **Fixing orphaned links appearing in an audit tool despite already being redirected:** go into the SEO plugin (Yoast) settings and confirm the sitemap is set to automatically update, then rerun the audit tool's crawl — most crawl/audit tools (~99% per Denray) work off the sitemap, so a stale cached sitemap causes false-positive orphan reports even when the live sitemap is already correct.
- **Deindexing a duplicate/leftover homepage** (e.g., an old "Home 2.0" page already 301-redirected to the real homepage but still flagged by audit tools): in WordPress, hover the page in the Pages list → Quick Edit → change Status from "Published" to "Draft." This removes it from the sitemap; rerun the audit afterward and the error clears. (A redirected page that's still marked "Published" stays in the sitemap and keeps getting crawled even though it just bounces away.)
- **Tag/archive page layout (WordPress):** "Edit Tag" cannot change the page's layout/template. To actually edit that template, go to Appearance → Theme File Editor and edit the relevant theme file directly — only recommended if comfortable editing code; otherwise leave it alone since it isn't hurting SEO anyway.
- **Handling junk query-string URLs** (e.g., leftover from an old hack/spam injection): in GSC or an audit tool, ignore everything in a URL from the "?" onward — what's left after stripping the query string is usually just the homepage or another legitimate page. These auto-generated pages typically just resolve back to the homepage and can be left alone, especially when there's no access to delete them (created by an unknown plugin/theme/third-party app, sometimes from a past cyberattack).

## Rules / dos & don'ts (keep every threshold, number, specific)

- Location pages matter far more for service-based businesses tied to a geographic area than for product-based businesses.
- A nationwide/worldwide service business (example: web hosting/programming) does not benefit from location pages — unless it's targeting one specific area.
- Every page on the site must be reachable by clicking through from the homepage; if not, it's an "orphaned page" and needs internal links.
- Paid Google Ads clicks do **not** harm organic SEO at all — PPC and organic are treated entirely separately by Google. The only real "cost" is that ad-driven traffic stops the moment spend stops, unlike organic content which keeps generating visits without ongoing payment.
- After a relaunch: checking whether URLs changed is described as "the number one most important thing" to verify — even a www/non-www change counts as a different URL requiring a 301.
- Merely having 404 pages on a site does **not** hurt rankings by itself.
- What **does** hurt rankings: linking from live content pages into 404s.
- Elementor/page-builder sites commonly generate large numbers of harmless template/category pages that show as "not indexed" — one client site referenced has as many as 20,000 such template pages; none of them would ever rank anyway and this is not a problem to fix.
- The two "not indexed" reasons in GSC actually worth investigating: "Crawled – currently not indexed" and "Not found (404)." Reasons like "page with redirect" or "duplicate/different canonical URL" are expected noise from template pages.
- Tag pages essentially never rank: "for every single case that we've ever worked on at Hey Tony, we've told clients to never use tags" — don't spend effort trying to optimize or fix them (e.g., missing H1s on tag pages is not a real issue).
- Junk/spam-generated query-string ("?") URLs can be ignored entirely in audits — not real pages worth chasing.
- A Google Business Profile is assigned a permanent CID number once it has existed for roughly 2+ weeks; that CID stays valid "basically for life," regardless of whether the profile's share link ever expires or details change later.
- Meta descriptions: keyword position (earlier = more weight) matters more than mere presence — applies to any search query, not niche-specific.
- Avoid literal, repetitive keyword stuffing in headlines/H1s — Google can detect this "over-optimization"; semantically related phrasing (e.g., "metal roofing in Vancouver" vs. "Vancouver metal roofing contractor") is treated as equivalent by Google, so natural wording is fine and preferred.
- Never use generic CTA text like "Contact Us" — always make anchor text descriptive of the service + location, both for readers and for crawlers/AI that can't infer context from generic text.

## Tools, prompts & resources (exact prompt wording if quoted; tool names; settings)

- **whatcms.org** — paste any URL to identify the CMS/builder a site runs on; used live to confirm "Adobe Dreamweaver."
- **Ubersuggest** and **SEMrush** — used to check whether an existing site's pages are ranking/getting traffic before deciding a migration approach; SEMrush also referenced for page-audit/orphan-link scans.
- **Google Search Console (GSC)** — Performance tab (too soon for ranking changes 1 day after a relaunch); Indexing → Pages report (watch for a sudden drop in indexed-page count; review "Not found (404)" and "Crawled – currently not indexed" buckets); Sitemaps tab (submit each segmented sitemap individually).
- **Yoast SEO** (WordPress plugin) — confirm sitemap setting is "automatically update" so third-party crawlers see current URLs, not a stale cached version.
- **Plerdy** — WordPress plugin that surfaces a Google Business Profile's CID number/link directly (Denray initially mis-said the name as "Plepper," then corrected to Plerdy).
- **"Ludocid" manual lookup** — alternative way to find a CID: view page source on the GBP listing and search "ludocid."
- **CID link format:** Google Maps URL + `?cid=[number]` — use this as the clickable address link on the client's website rather than the plain GBP share link.
- **Hey Tony's own audit/page-audit tool** — referenced alongside SEMrush as a crawler that reads the sitemap and can surface stale/orphaned-link false positives if the sitemap cache is outdated.
- **WordPress admin paths used live:** Pages → hover row → Quick Edit → Status field (Draft vs. Published) to deindex a duplicate page; Appearance → Theme File Editor to edit tag/archive template layout.

## Tradeoffs & nuance

- Migrating a hand-coded site to WordPress is worth it mainly for long-term editing ease, but risks losing existing SEO value if done carelessly — the decision should hinge on whether the current site is actually ranking/getting traffic (checked via Ubersuggest/SEMrush + GSC/Analytics), not just on the developer's comfort with the old code/CMS.
- Preserving URLs exactly (including www vs. non-www) is treated as non-negotiable for protecting rankings during a migration, but doing so on a site with years of published content can still take significant time, since every ranking page must be manually recreated/matched.
- Footer vs. main-menu placement for location pages carries no ranking penalty either way — it's purely a client/design preference, provided internal links exist so pages aren't orphaned.
- Multi-city expansion only makes sense if keyword research confirms actual search volume for each [keyword + city] pair — copying a competitor's city-page layout is fine structurally, but volume must be validated per city rather than assumed.
- Keyword matching in copy involves a tension between sounding natural and hitting the "exact" keyword — resolved by Google treating close semantic variants as equivalent, so natural phrasing beats forced, repetitive exact-match wording (which reads as over-optimized).
- 404s, orphaned pages, and duplicate content are mostly cosmetic/audit-tool issues, not necessarily real ranking problems — the nuance is separating genuine issues (linking into 404s, a live/crawlable duplicate homepage, a page truly unreachable via internal links) from noise (harmless template/tag pages, stale sitemap caches, ancient hacked junk URLs that can't even be accessed to delete).
- The CID link vs. the standard GBP share link both point to the same profile, but CID is framed as having a slight technical/durability advantage since it's tied directly into Google's own system rather than a share link — a subtle distinction most site owners wouldn't otherwise think to make.
