## Tactics & step-by-step how-to

- **Changing a page's URL/parent path:** use a 301 redirect to pass authority to the new URL. Expect to lose *some* backlink value — a redirect passes authority through, but "a little bit less because that will still be a new page." Visitor click-through still works fine via the redirect chain.
- **Before changing any URL:** check Google Search Console traffic/impressions on that page first. If there's no traffic/impressions, redirecting is low-risk ("we can make that redirect, it's not going to impact anything"). If there's meaningful traffic (e.g. ~100 people/day), redirecting carries real risk of losing traffic — weigh it before acting.
- **One-time campaign/webinar landing pages** (registration page, confirmation page): set to **Draft** in WordPress once the campaign/webinar is done, so Google doesn't see them at all. WordPress should offer Schedule / Publish / Draft (some versions have a scheduled-draft option) — exact options depend on WP generation/version.
- **Evergreen landing pages** (e.g. an always-live PDF-download page promoted repeatedly on LinkedIn): keep live, but internally link them from relevant pages (add to navigation, or link from a related service page or blog post) so they're never an orphan page.
- **Avoiding orphan pages generally:** internally link any page you want to stay indexed — e.g. link a webinar landing page from a blog post or service page that references "supportive resources such as webinars."
- **Live site/page audit method used on the call:** install the "Hey Tony page audit extension" (free) first, then screen-share and walk the page audit output live.
- **H1 placement fix:** get the H1 to literally be the first tag on the page. If what's visually at the top is just large styled body text (not a real H1), demote it to a paragraph and increase its font size manually, then make the real H1 tag hold that top position — this is what signals to Google, as it crawls top-down, what the page is about.
- **Heading hierarchy logic (how to think about H1/H2/H3):** H1 = the broadest single topic the page is about (e.g. "Chicago newborn photographer"). H2 = supporting sub-topics that add context/depth under the H1 (e.g. family, maternity). H3 = more specific detail supporting the H2 above it (e.g. "affordable newborn"). Each level adds "more depth, more context, more specification."
- **Keyword-per-heading-level rule:** H1 — must contain the exact target keyword, no exceptions. H2 — should contain the keyword in "all" or at least a "healthy mix or healthy majority" of them (don't force it into literally every H2 if there are many, e.g. 10 H2s — that reads as stuffing). H3 — optional/flexible, still encouraged.
- **Business name in H1:** remove it. Keep brand name in the page `<title>` tag only (it's already visible there and in the URL); the H1 should be keyword/topic only.
- **Benchmarking word count for a money page:** pull up competitor pages ranking for the same keyword (via a free tool — Hey Tony's resources, or Semrush's free trial) and check their word count. Match that range, then go "just one-upping them slightly" (e.g. if they're at 2,000 words, land around 2,005) rather than picking an arbitrary target.
- **When a page's content starts drifting off-topic** (e.g. a newborn-photography homepage loading up on unrelated maternity content): don't dilute the core page — instead add a button/link out to a dedicated page for that subtopic (e.g. link the "About" blurb out to a full About page).
- **Scaling local SEO with location pages:** once main service pages are solid, add one page per suburb/area that has real search volume behind it. Each location page needs genuinely different content from the others and from the main service page, and should fold the location term directly into the H1 (e.g. "Skokie newborn," not just "newborn photography") to avoid cannibalizing the main service page.
- **Diagnosing keyword cannibalization:** two pages are cannibalizing each other if they're both fundamentally about the same core keyword/topic, even in slightly different phrasing (e.g. "Chicago Newborn Photography" homepage vs. a second page titled "Newborn Photography Chicago" — same premise, different word order, still cannibalizing). Location-specific pages are NOT cannibalizing as long as the location term clearly differentiates them.
- **Requesting indexing for a "crawled but not indexed" blog post (GSC):** use "Inspect any URL" at the top of Search Console, paste the URL, check its status. If it shows as not indexed, click **Request Indexing**. This doesn't guarantee indexing, but it signals Google to recrawl the page, which raises the odds.
- **Indexing timeline expectation:** give it roughly **2–3 months** before treating a "crawled, not indexed" blog as a real problem.
- **While waiting on indexing:** internal linking is "the best, most practical thing you could do right away" to increase the odds — link to the new/unindexed post from other relevant pages on the site.
- **How to add internal links efficiently across existing content:** go through relevant existing pages/blogs and add links either as inline anchor text within the body copy (naturally referencing a related resource, e.g. a "home selling" post linking out to "home staging" and "home staging lighting" posts) or as a "suggested/recommended posts" block. Best practice is a mix of both, but weighted toward inline contextual links placed **higher up** in the content — Google values that more than three suggested-post links dumped at the bottom.
- **Consolidating split Google Analytics / Search Console access across two email accounts:** go to the gear icon (Admin) → **Account Access Management** → click the circular "+" in the top-right → **Add user** → enter the correct/current email → set as **Administrator**. Then remove access for the old email. Do this for whichever account (email) is currently wrong.
- **Duplicate/leftover GA4 property:** if a second measurement ID/property exists that isn't the one actually receiving live traffic, deactivate/delete it — keep only the property wired to the live site and to Search Console.
- **Mismatched embedded measurement ID:** if the analytics tracking code embedded in the site doesn't match the "correct" GA account, update the measurement ID in the site code first, before touching anything else.
- **Domain property vs. URL-prefix property in GSC:** if a site shows up registered as both, that's normal, not harmful. For the most accurate/complete picture, use the **Domain property** — it aggregates everything on the domain (all subdomains, http/https, www/non-www), whereas URL-prefix property is scoped to just that one exact prefix.
- **Meta description keyword matching:** keep the target keyword phrase as close to exact-match as possible in the meta description — don't insert extra connecting words (like "in") even if it reads more naturally, because that changes the keyword.
- **Keyword density benchmarking:** check how many times competitors use the exact keyword on their ranking page. If they use it ~3 times, cap yourself around 4–5 uses ("probably like four or five times at the most") — don't go overboard chasing volume.
- **Exact-match placement rule:** put the exact keyword (no added words) in H1, H2, and a couple of times through the body copy. Variations of the keyword can be used as many times as feels natural elsewhere.
- **Verifying a cannibalization-tool flag before acting on it:** if a tool flags multiple URLs with identical/near-identical H1s/titles as cannibalizing, check whether those extra URLs actually 301-redirect to the canonical page. If they do, they aren't live and aren't really cannibalizing — the tool likely isn't detecting the redirect. Report that gap to the tool owner rather than trying to "fix" pages that already redirect.

## Rules / dos & don'ts

- 301 redirect when a URL must change — but understand it passes *less* authority/backlink value than keeping the original URL; avoid changing URLs unless necessary.
- Always check Search Console traffic/impressions on a page before changing its URL.
- Draft one-time-use pages (webinar registration/confirmation, one-off campaign landers) immediately once the campaign is over.
- Never leave orphan pages (unlinked from anywhere on the site) — internally link evergreen pages instead.
- H1 rules: must be the literal first tag on the page; must contain the exact target keyword; must NOT contain the business/brand name.
- H2 rule: keyword in "all" H2s or at minimum a healthy majority — not necessarily literally every one if there are many.
- H3 rule: keyword optional but encouraged.
- Money-page word count: benchmark against top competitors targeting the same keyword; don't pad with filler — new content must add topical depth, not dilute the page's core focus.
- **Don't change your domain name if you can avoid it** — you lose accumulated domain authority. (Root cause of Bill's traffic collapse: domain change + rebuild with no redirect set up.)
- If expanding services/niche (e.g. photography → + videography), build new dedicated pages for the new offering rather than folding it into the same page or forcing a domain/name change.
- Don't run multiple pages after the identical or near-identical keyword/topic — differentiate by keyword variation or by geography.
- **Don't send visitors off-site to other websites from your own site** — per Matt's standing guidance, "sending people to other websites is not ideal on your own site"; self-referential link exchanges between creators "mean nothing." (Ariel removed her Resources page on this basis.)
- Meta description: never alter the exact keyword phrase (e.g. don't insert "in") even if it reads more naturally — keep exact-match.
- Don't keyword-stuff to inflate density — cap based on what competitors are actually doing (+1–2 uses over their count), not an arbitrary number.
- WordPress is the team's generally recommended platform for maximum SEO control, versus website builders like Showit, which have header-tag/structural limitations (still being researched by Elliot).
- In GSC, prefer the Domain property over the URL-prefix property for the most accurate data.

## Tradeoffs & nuance

- Redirecting a changed URL preserves most but not all backlink/authority value — the loss is inherent and unavoidable versus keeping the original URL. The decision should weigh existing traffic: near-zero traffic makes redirecting low-risk; meaningful daily traffic (Elliot's benchmark example: ~100/day) makes it a real risk to weigh.
- Short-tail vs. long-tail keyword strategy for a money page was raised as a live, unresolved tension by Ariel ("I'm still like iffy on the short-tail keywords versus long-tail") — the call didn't resolve it beyond the general H1/H2 keyword rules and the location-page expansion strategy.
- Natural-sounding copy vs. exact-match SEO signal is a real tension: variations are fine and encouraged in body copy generally, but the exact-match phrase still has to anchor H1/H2 and a couple of body instances (Oliver's "ayahuasca retreat in Colombia" vs. "ayahuasca retreat Colombia" question).
- Location pages targeting the same core service in different geographies sit right at the edge of cannibalization — they're only legitimately "different enough" if the location term is clearly present in the heading and the content is genuinely distinct per location; otherwise the pattern looks identical to true cannibalization.
- Platform tradeoff: Showit offers strong visual drag-and-drop control but limited HTML/heading-structure customization; WordPress offers more SEO/technical control but requires more skill ("I'm a photographer, I have no skills," Ariel said). Ariel is deferring a possible platform switch to a slow season rather than acting now.
- The 2–3 month indexing delay is framed as normal, expected SEO friction rather than a technical fault — but Elliot still recommends active mitigation (internal linking, Request Indexing) rather than pure passive waiting.
- A cannibalization-detection tool's flag is not proof of an actual live problem if the flagged pages already redirect — underscores manually verifying automated tool output before acting on it, and looping back the false-positive to the tool's owner rather than "fixing" pages that are already resolved.
- Elliot repeatedly frames guidance as provisional where he's still researching: Showit's SEO limitations/tier differences, the exact cause of Bill's sitemap fetch failure, and the mechanics of Ariel's duplicate GA/GSC properties were all explicitly deferred to next week's call rather than fully resolved live.
