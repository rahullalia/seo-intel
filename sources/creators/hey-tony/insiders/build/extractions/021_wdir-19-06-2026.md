## Tactics & step-by-step how-to

- **Diagnosing why a weaker competitor outranks you in AI Overviews (Jason Bush's case):** search your target keyword 2–3 times across different days and log which sites the AI Overview cites each time. Click through the small source icons under the AI Overview snippet to see exactly which pages it's pulling from. Check whether those cited competitor pages are themselves showing up on a third-party "list" page (e.g. "Top Photographers in Atlanta") — the AI may be sourcing from curated list content rather than rewarding the competitor's own on-page SEO.
- **Investigating an unexplained Search Console traffic/click spike (Ariel's case):** GSC → Search results (Performance) → set a custom date range bracketing the spike (Ariel used June 13–17) → check the **Pages** tab to see which pages drove the traffic → check the **Queries** tab to see what was actually searched (often branded terms — company name, coach's name, product name — rather than service keywords). Also usable: **Insights** tab → filter to "trending up" to surface pages gaining clicks fast.
- **Finding which counties/cities actually search your service when GSC only reports at the country level (Anthony's case, B2B/statewide service):** use Google Analytics/GA4 for city-level acquisition data instead. Ask ChatGPT: *"How do I find acquisition for a specific page in Google Analytics/GA4."*
- **Before committing to a keyword, Google it yourself and check what actually ranks (Jennifer's case):** she was targeting "WordPress web design" as her keyword, then Googled it and found the results were all about the WordPress software itself, not web-design services — i.e., she'd built around the wrong keyword variant.
- **Content-angle idea for web designers:** target people who already tried DIY-building their own site (WordPress/Wix) and hated the result / want a redo, rather than assuming everyone searches by platform name — e.g. a post framed like "I'm dying trying to build my own website."
- **Location-page rollout cadence:** write fully unique copy per location (not a template with only the city swapped). Ship **one new location page per week** (two/week if aggressive) — a 12-location build finishes in ~3 months without burning out. After 3–4 months, check whether the pages actually rank; if they don't, simplify the approach (e.g. move toward the more templated/duplicate style some competitors use).
- **What goes into a location page's content (florist example walked through live):** delivery-time specifics for that place (e.g. "same-day delivery within 6 or 12 hours"), named local landmarks/venues (funeral homes, wedding venues, parks), and seasonal color commentary (e.g. a park is great May–September but hotter mid-summer, with prep tips).
- **Location-page interview prompt (parallel to the existing blog-interview prompt):** ask yourself a few questions per location and turn the answers into page copy (not a blog post) — e.g. "What do you like most about this location? How's the lighting? If it's rainy, can we still shoot here?"
- **Location vs. blog post rule of thumb:** static/evergreen location info that should rank for the money keyword = a **page**. A specific one-off question/topic = a **blog post**.
- **Navigation structure for many locations:** put a "Locations" link in the header/footer → it goes to one hub page listing every location → each location name links out to its own individual page.
- **Seasonal/holiday money pages instead of blog posts (AJ's gift-card business):** build a dedicated page per key season (Black Friday, Christmas, Valentine's Day). Keep the URL live and indexed year-round, but pull the link from the homepage/nav when out of season — Google still knows the URL exists. Before/during the next season, either restore the nav link or point a timely blog post at it (florist example: Valentine's Day is never in the permanent nav, but a seasonal post like "best Valentine's Day flowers for your fiancé/wife/husband" links to the page so Google can still crawl it).
- **Fixing a duplicate-H1 / duplicated-content mobile bug in Avada (Marisa's case):** don't duplicate the whole block to show one copy on desktop and a hidden/different copy on mobile — that loads the same content twice on every pageview. Instead, open the block's own design settings and set different values per breakpoint (desktop/tablet/mobile) on the *same* element — e.g. one font-size value for desktop, a different one for mobile, no duplication. Image sizing works the same way. A different **background image** per breakpoint is fine, as long as the text itself isn't duplicated as a second element.
- **Claude Code fix for Avada responsive issues:** copy the block's default-editor code from the WP backend, paste it into Claude Code, and prompt: *"make this mobile friendly in the same blocks without duplicating the content."*
- **General ChatGPT/Claude workflow for Avada mobile-CSS bugs (shared by another member):** paste the problem in, explicitly state you're using Avada in WordPress, and have it walk you through fixing responsive image ordering (before/after/sideways settings) and fixing text that bleeds to the edge of the mobile screen (text-block padding/margin).
- **Image-optimization priority order (don't try to convert everything at once):** (1) money pages first, (2) new blog posts as you publish them going forward, (3) then circle back to older posts that have impressions in GSC but aren't ranking well.
- **Free WebP conversion for anyone without Lightroom/Photoshop:** Google "convert JPEG/PNG to WebP" and use a free converter (Matt pasted a link in the call chat — "doesn't cost anything, and it's quite good"). Photographers with Lightroom should use its built-in **preset export** to output WebP directly.
- **Press release + GBP name change can run concurrently (Neri's case):** submit the press release as soon as it's ready — don't wait for Monday. Change the Google Business Profile name at the same time as long as you're holding the DBA ("doing business as") paperwork in case Google asks for re-verification.
- **Never publish the press-release text on your own site** — the release outlets are already linking to you, and hosting the same copy yourself creates a reciprocal-linking pattern Matt advises against. Share it on social media and your email list instead.
- **Building a "reviews" aggregator microsite** (tactic from Edward Sturm, relayed secondhand — Matt hasn't run it himself): stand up a separate domain (e.g. "[businessname]reviews.com"), paste in testimonials/reviews pulled from every source (Google, Facebook, direct client feedback — doesn't have to be all positive), then add **one link to it from an indexed blog post** on your main site to seed its authority. Claude Code can build the whole microsite; the build itself "shouldn't take more than a couple hours" if you know what you're doing.
- **Reviews on money pages:** hand-paste 2–3 real reviews directly into the page copy (not a carousel plugin), rotating which reviews appear on which page so the same text isn't repeated everywhere. Link out to the full Google Business Profile / Yelp listing for "see more." Formatting is flexible — H2, H3, or plain paragraph text all work.
- **New post/page indexing workflow:** link the new URL from at least 3 older/existing blog posts at publish time, then don't request a manual crawl — just wait roughly a week and check whether it's indexed before requesting indexing manually.
- **Homepage FAQ + blog linking:** a core recurring question (e.g. "When's the best time to do maternity photos?") can get a permanent short-answer spot on the homepage with a "see full breakdown" link to the fuller blog post — but don't do this for every post, only for genuinely core content.
- **Don't request a GSC recrawl on pages you're still actively editing** — wait until the page is actually finished before asking Google to look again.

## Rules / dos & don'ts (keep every threshold, number, specific)

- **Don't repeatedly revise your homepage.** Every edit forces Google to re-evaluate "where does this belong" — Matt's own SEO-in-Hamilton service page was built once, minimally optimized, never touched again, and hit #1 after ~1 year purely from blog posts + internal linking + anchor text (topical authority).
- **Don't worry about your About/Contact page "competing" with your homepage or trying to make it rank** — the homepage carries the business/ranking content; About page is just "a little more about me." Matt doesn't have an About page at all — everything's on his homepage.
- **Zero search volume doesn't mean skip the keyword.** A 0-volume keyword (live example: "commercial trash compactor NJ") can still be worth a page — near-zero volume usually signals low competition, and even one converting searcher is a win competitors are ignoring. (Still weigh the tool's competitive score, not just raw volume.)
- **Never use hidden text or hidden pages** to stuff SEO content while hiding it from users. If content is deliberately hidden from users, Google reads that as "these people don't want me to see this" and won't reward/show it.
- **Don't name your business/page with "Best"** (e.g. "Best Atlanta Photographer") — reads as less credible/"jankier." Use a real name + descriptor instead (e.g. "Jason Bush – Architectural Photographer in [city]").
- **Don't use a review-carousel plugin.** Found on a client site pulling in roughly **1,000 extra words** of markup on some pages, hurting load time; also bad UX — users scroll past carousels rather than clicking through them.
- **Don't repeat the identical review verbatim on every page** — rotate 2–3 reviews out of a larger pool per page.
- **Location pages must be genuinely unique content per location**, not a template with only the city name swapped — though if literally all your competitors are doing the swap-only approach, that itself signals low competition and either approach might work; test unique content for 3–4 months, simplify only if it fails to rank.
- **Press releases:** fine to submit same-day/Friday, no need to wait for Monday. Never host the release copy on your own site.
- **Reviews belong on every money page** (not just a dedicated reviews page), 2–3 per page, hand-pasted.
- **GBP name changes tied to a DBA/press release are safe to run in parallel** — if Google declines the name-change verification, the profile simply reverts to the old name; it does not go down or get suspended in the process.
- **Don't over-check rankings or over-request indexing** (called out directly re: David Jones checking rank "2+ times a day") — publish, internally link, walk away, check back in about a week.
- **HeyKeywords semantic keywords:** near-synonym terms (e.g. "photography" vs. "photographer") will show similar volume because the tool treats them semantically — don't worry about cannibalization between them; use them interchangeably in copy.

## Tradeoffs & nuance

- AI Overview citation appears decoupled from organic ranking — Matt frames his sourcing theory as still just "a theory," not a proven mechanism, and the cited-site set is unstable across repeated searches of the same keyword (~30% consistency across 3 searches in his test). A single "why did they beat me" snapshot comparison is unreliable; look for patterns (e.g. curated list pages) instead.
- Location pages: fully unique content per location is the safer long-term bet, but Matt concedes duplicate-with-swapped-locale-name pages are what many real competitors — including a podcast guest he referenced — are doing and reportedly ranking with in low-competition niches. His resolution: try the harder/unique approach first, give it 3–4 months, simplify only if it fails.
- Zero-volume keywords are attractive for low competition, but Matt notes the tool's competitive score should still be weighed alongside raw (zero) volume, not ignored.
- The reviews-aggregator microsite is an unproven, secondhand tactic — Matt hasn't run it himself, and it's actively disputed by another SEO practitioner's public content (the "no authority" argument). His stance is that it's cheap enough to test (a couple hours to build, one internal link to seed authority) rather than a guaranteed win.
- Seasonal money pages retain SEO value year-round only if you deliberately preserve an internal-link path back to them in-season (nav restoration or seasonal blog posts) — orphaning them completely defeats the purpose.
- Review carousels look visually nicer ("but it looks so pretty") but trade off page speed and real engagement — Matt explicitly weighs aesthetics against SEO/UX cost and comes down against carousels.
- Google's "Preferred Sources" feature is a potentially powerful lever for influencing AI/search visibility in your favor, but as of this call has no known activation mechanism beyond a user manually clicking to opt in — even paid traffic pointed at the link doesn't bypass that requirement, leaving it an open, unsolved growth question.
- Backlink tools disagree with each other and with GSC by wide margins for the same domain (325 vs. ~1,100–1,300 vs. 2,700 depending on source/metric) — none should be treated as a definitive count; direction/trend matters more than any single absolute figure.
- B2B/client-facing site design (Jason Bush's case) creates real tension between a clean, professional-looking site for sophisticated buyers and SEO-favorable elements like visible reviews. Matt's resolution: keep reviews on money pages in a restrained, non-carousel form even in a design-conscious B2B context, rather than omitting them.
