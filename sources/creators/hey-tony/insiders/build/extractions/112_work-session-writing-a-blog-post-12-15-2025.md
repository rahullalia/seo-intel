# 112 — Work Session: Writing a Blog Post (12.15.2025)

## Tactics & step-by-step how-to

- **Core content concept (the exercise for this session)**: write a blog post about the downsides/problems of hiring or buying YOUR OWN product/service type. Title pattern: "The problems with hiring/buying [X] that no one talks about" (or "the downsides of..."). Counterintuitive on purpose — competitors won't write this, so you become the honest/transparent voice. Must be genuinely honest about real pitfalls, not a disguised sales pitch ("we're better because we don't do this").
- **AI writing process**:
  1. Paste the group's standard recurring prompt into ChatGPT (same prompt used in prior sessions; walks you through a Q&A before drafting).
  2. Answer ChatGPT's clarifying questions (took most attendees ~15–20+ min).
  3. Review the first draft — it typically comes back bullet-heavy, not enough sentences/paragraphs.
  4. Copy output into a fresh doc (Google Docs/Word) to edit alongside the chat.
  5. For any section that's too bulleted, paste it back into the SAME ChatGPT conversation and say it needs rewriting into sentences/paragraphs (see exact wording below).
  6. If the rewrite runs long, ask to shorten to 3–4 paragraphs and to drop the AI-tell closing phrase "and finally..."
  7. Target length: roughly **1,000 words** ("probably fine").
  8. Add a "Final Thoughts" / "Conclusion" section as an H3 heading tag.
- **Internal linking workflow**:
  1. Grab your site's post sitemap (Yoast/Rank Math generate one; on Shopify just use whatever sitemap exists, even if it mixes in product/service pages — fine).
  2. Copy the entire sitemap page content, paste into the same ChatGPT conversation with: "using this sitemap, give me three internal linking opportunities for this specific blog post to link out to."
  3. Manually place the 3 suggested links into the body at sensible anchor text.
  4. Separately ask ChatGPT for one more link opportunity to your core service/money page — it can infer the right page from prior conversation context even if you never fed it that URL.
  5. Add a natural CTA anchor (e.g., "check out our SEO packages here") linking to that service page.
- **Getting a brand-new post indexed faster**: rather than waiting on Google to crawl it organically, immediately add 2+ internal links pointing TO the new post from your own existing, already-ranking related posts.
  1. Google your own target phrase (e.g., "hiring an SEO agency") to find your already-ranking related posts.
  2. Open one, add a plain-paragraph (not heading) "Related" link pointing to the brand-new post — called this "the lazy way to do internal links."
  3. Repeat on a second existing post so the new page has 2+ inbound internal links right away.
- **Yoast's internal-link-count feature** (posts list view): shows, per post, how many pages link TO it and how many pages it links OUT to. Used live to check pages sitting at 16, 9, 3, and 1 internal link — flagged that any post sitting at 1 needs more.
- **TL;DR / key-summary block**: ask ChatGPT for "a TLDR at the top of this blog post, five points max, call it 'key summary'" and paste it in as an H2 at the very top of the post.
- **Publishing steps (WordPress-specific but generalizable)**:
  1. Paste ChatGPT's output straight into the post editor.
  2. Run "Clear Formatting" to strip inline styles/spacing junk while preserving heading tags.
  3. Assign exactly one category (no tags).
  4. Set a featured image + alt text (alt text = the image/post title).
  5. Generate a meta description via prompt (below), pick the best of the ~5 returned.
  6. Publish.
- **Featured image workflow** — three sourcing methods:
  1. **Unsplash**: search using the literal blog title/question as the search term; free, royalty-free, usually no attribution required, just click download.
  2. **Your own media library**: search your existing WordPress media for images already in a style/brand you like (e.g., "cartoony" images), reuse that style.
  3. **ChatGPT image generation**: gather 2–3 example images from your own site, then prompt (exact wording below) to generate a new on-brand featured image with no text baked in. Can also just paste a link to your own website and ask ChatGPT to match that site's visual style.
- **Compress every image before upload**: check file size (Get Info) first; if it's over roughly 1MB, run it through a free PNG-to-WEBP converter (just Google "PNG to WEBP") before uploading, to keep site speed fast. Demoed twice: 1.1MB → 27KB, and 1.9MB → 102KB, "looks exactly the same."
- **Infographic add-on**: prompt ChatGPT to "make an infographic for this page," compress it to WEBP the same way, drop it into the post body, and separately post it to Pinterest — infographics are the type of asset other sites sometimes re-embed with credit, which becomes a backlink.
- **Canva image-editing shortcut** (to avoid the copyright trap below): drag a stock element in, then add something on top of it (post title text, an outline effect, another graphic element) BEFORE exporting — even if the text ends up cropped/hidden behind the subject, that edit is what keeps the export compliant.
- **Deciding blog post vs. case study vs. service/money page**: literally Google the target keyword and see what content type is already ranking (case study, blog post, guide, or service/product page) — match that type, because that's what users/Google expect for that query.
- **Deciding whether to write a DIY guide instead of gating a service**: if the SERP for your target keyword is dominated by how-to guides, write the guide and actually teach the reader to do it themselves rather than trying to force a sales page — builds trust/authority, and a portion of DIYers convert to hires anyway.
- **Location + service blog rotation** (for multi-location businesses): alternate blog topics between services and locations rather than mixing several locations into one post.
- **Choosing which existing pages get new internal links**: leave pages already ranking position #2–3 alone (they already get clicks); focus new internal links on pages sitting at the bottom of page 1 or lower.
- **Money-page architecture for a multi-service business** (wedding photography/videography example): one dedicated page per core service, plus separate micro-niche pages for specific searchable sub-services (elopement photographer, proposal shoot, engagement shoot) even if those are normally bundled into a full package. Case-study/highlight pages should be organized around a searchable entity (e.g., "weddings at [venue/vineyard name]"), never around the couple's personal names, since nobody searches for that.
- **Homepage keyword strategy**: homepage doesn't need to chase one exact money keyword — it can carry a broader combined phrase (e.g., "wedding photographer and videographer [location]"), while separate dedicated pages target each individual service.
- **Order of operations (new content vs. fixing old pages)**: don't try to overhaul the whole site before publishing. Keep the weekly blog cadence non-negotiable; use whatever spare time is left over to optimize one underperforming existing page.
- **Hey Tony's own client SEO cadence** (disclosed as their actual process): two deliverables per week per client — one new blog post, and one existing service/product page rewrite/optimization.

## Rules / dos & don'ts (keep every threshold, number, specific)

- Never frame a "problems with X" post as a hidden sales pitch — must list real pitfalls honestly, including ones in your own industry.
- Don't keyword-stuff multiple locations into one keyword phrase: adding "in Hamilton" AND "Toronto" AND "Vancouver" only helps you rank for the ONE location you actually used most cleanly — you won't outrank someone who used just "Toronto" for the Toronto search, even though your phrase is longer/more "complete."
- Only ONE location per blog post/page when you run multiple location pages.
- Internal links: **minimum 3–5 per page**. External links: **minimum 1 per page**. Contact/about pages are exempt from this.
- Don't exceed roughly **50–100 internal links** on a single page — unreadable for people, and signals something's off to Google.
- Categories: exactly **one category per post**, never use tags ("they just create a bunch of redundant pages that bloat your website"). Keep total categories to **5–10 max** sitewide.
- Compress every image before upload — don't upload full-size 1MB+ images; it slows the site.
- **Canva legal trap**: never export a bare/unmodified stock element straight from Canva's library — that violates Canva's copyright terms. Canva has directly contacted at least one team member's clients over this, demanding the image be taken down or paid for. Canva Pro costs **~$20/month**; its background remover is called out as excellent.
- Don't run a structural/stylistic experiment on every single post — space experiments out to roughly **every 2nd–4th post** so you can actually attribute what worked.
- Don't chase a perfect readability/content score (Yoast or similar) — "you can't get 100, and if you do get 100, doesn't mean it's going to be any better optimized than if it's at 50." Treat automated scores (Flesch reading ease, passive-voice %, transition-word %, "not enough content" warnings) as directional, not gospel — they can be flat-out wrong on long pages.
- Patience rule: SEO takes months. Check performance **about once a month**, not daily — checking daily causes disappointment and is "what causes people to give up with SEO."
- A brand-new page/post will not show in Google search at all for at least the first couple of days — normal, not a mistake, don't panic; "you have to be patient with SEO."
- Want guaranteed instant results? That's what paid ads are for, not SEO.
- Don't be afraid to teach the audience to DIY the exact thing you sell — if guides dominate the SERP for your keyword, match that intent rather than forcing a service/product page.
- Don't chase people who re-post your images/video without credit — not worth the hassle; volume of new content produced makes it a non-issue. Contacting them to ask for credit/takedown is optional, a lawsuit is "a huge, huge hassle."
- Logo on featured images: optional, not required — Matt's own site images and social content mostly carry no logo.
- Don't feel obligated to be highly active on every secondary platform (Pinterest, Tumblr, Medium) — post/pin "when you can" rather than committing to constant activity; low-effort, occasional posting is still worth doing.

## Tradeoffs & nuance

- Writing about a "problem" nobody is literally searching for (Pilates aches/posture) can still be worth it for topical authority, even without direct search-demand proof — a judgment call, not a guaranteed traffic play.
- TL;DR/"key summary" blocks are explicitly unproven in Matt's own words: "we're experimenting with that still... sometimes it really works, sometimes it doesn't really work."
- Location-in-keyword is a tradeoff, not a free win: it helps you rank locally but does nothing for other cities even if you list them all, and stuffing several locations into one phrase can hand the win to a competitor using a single, cleaner location keyword.
- Internal-link volume is a balance: too few (0–1 inbound) leaves a page orphaned; too many (50–100+) hurts readability and looks manipulative to Google — the 3–5 range is the target.
- Which existing pages to prioritize for new internal links depends on current rank: #2–3 already gets clicks (leave alone); bottom of page 1 or worse benefits most from added links.
- Automated readability/content-score tools are approximate and can be flat-out wrong (flagged "not enough content" on a long page) — useful as a rough aspirational guide, not a hard requirement; a 100 score isn't proven to outperform a 50.
- Experimentation cadence matters: testing something new on every post makes it impossible to isolate what caused a ranking change; spacing tests out (every 2nd–4th post) preserves the ability to attribute results.
- Canva tradeoff: fast and has strong tools (Pro's background remover), but exporting an unmodified stock image can trigger real copyright enforcement from Canva against your own site — mitigated only by adding an edit before export.
- Image-sourcing choice is brand-dependent: some businesses prefer authentic real-life photography over stock/AI-cartoon styling for trust, but real photography costs more effort to produce — no universal right answer.
- Formal ChatGPT "Projects" (saved instructions) vs. a plain recurring chat: a Project would reduce repetition, but a normal ongoing conversation already retains enough context (services pages, sitemap, voice) that Matt didn't consider a formal setup necessary to demo live.
- Order of operations (new content vs. fixing old pages) is deliberately flexible: the weekly blog cadence is the non-negotiable constant, while page-optimization work fills whatever time is left — not a strict sequential gate.
- Blog post vs. case study vs. service page has no fixed formula beyond checking the live SERP — the same core keyword can deserve a different content type in different queries, purely driven by what's currently ranking.
