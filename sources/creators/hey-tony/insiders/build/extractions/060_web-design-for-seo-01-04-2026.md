# Web Design for SEO — 01.04.2026 (Leanne Jones, Leanne Digital)

## Tactics & step-by-step how-to
- Fixing a busy/low-readability hero background: add a subtle gradient over the image (demoed left-to-right) before placing text on top — doable in Canva. (glass jars/bottles site)
- Hero copy hierarchy demo: primary message (what you sell) largest → secondary selling point (e.g. "no minimum order") shown smaller/de-emphasized → tertiary detail ("fast shipping") last. (glass jars/bottles site)
- Diagnosing a "my site got slower after I added text over images" complaint: don't assume it's the text itself — open Google PageSpeed Insights and check the actual image-loading report before troubleshooting further. (glass jars/bottles site)
- Fixing slow-loading product images: convert JPEGs to a next-gen format (WebP) via a WordPress plugin (name garbled in transcript, heard as "image 5" — almost certainly a JPEG→WebP conversion/optimizer plugin). Separately, WP Rocket improves page speed but can conflict with JavaScript/site interactivity — turn on one feature at a time, retest the site after each, and turn a feature back off if something visibly breaks. (glass jars/bottles site)
- Removing a product photo's background to isolate it for a redesigned hero — demoed live with a background-removal tool. (going-wild pet site; repeated on Belle's calligraphy hero photo)
- Fixing an animated element that "catches" the user's scroll: identify the element with a fixed height causing the scroll-jank, then remove it or the animation — excess motion also pulls attention away from the CTA. (going-wild pet site)
- Rewriting a generic top-banner message ("we love pets") into an actual offer ("10% off coupon" or "free shipping over $50 spent"), and freezing that banner (stop it auto-scrolling/moving) so attention stays on the CTA button beneath it. (going-wild pet site)
- Making a CTA more visually directive: match the button color to the brand's existing playful palette (pink hero, teal button), then add a hand-drawn arrow graphic (sourced in Canva) pointing at the button to physically direct the eye — justified specifically because the brand's overall style is playful. (going-wild pet site)
- Contrast/readability self-check: mentally strip all color from the design — if the text isn't clearly readable in black-and-white, there isn't enough contrast, regardless of how good the two brand colors look together. (Carol's photography site; reused on Niri's jewelry site)
- Replacing a rotating 3-slide hero carousel: don't rotate between themes (lab-grown diamonds / engagement rings / book-an-appointment) in one carousel — give each theme its own full stacked section on the page (a banner for that theme plus a supporting product grid directly beneath it), because most visitors start scrolling immediately and never see slides 2–3. (Niri's jewelry site)
- Swapping a brand's clashing accent color: feed the existing dominant color into Pinterest to source a "sophisticated" complementary palette, land on a gold/navy pairing, then pull the exact hex code from the tool to replace the old accent (orange) with the new one (gold). (Niri's jewelry site)
- Fixing a CTA button that blends into the background: swap to a high-contrast combo (white background / black text) so it visually separates from the design around it. (ADH[D] therapy site)
- Breaking up one long block of body text: split into a repeating two-column layout (image + text), alternating which side the image sits on each time the pattern repeats (image-right, then flip to image-left). (ADH[D] therapy site)
- Deciding between a static "sticky" testimonial block and a scrolling one (client had gotten conflicting advice from ChatGPT to keep one sticky "so you don't lose it"): keep only the scrolling testimonial section and drop the static duplicate — running both split the visitor's attention. (ADH[D] therapy site)
- Building a 4-column features section: pair a purchased icon with a short text label per column instead of a dense paragraph. (ADH[D] therapy site)
- Turning a plain text reference into a real button for a stronger CTA — done for both an FAQ link and an email-list signup. (ADH[D] therapy site)
- Fixing a message-mismatch hero (visitors thought a lighting-install business was a sauna company, because the hero photo showed a bright sauna interior): reference a same-industry example site where the hero photo shows a person actively performing the actual service, then re-select/re-shoot the client's own photo so the service itself — not just the ambient setting — reads clearly; consider a photo + text-callout-over-image layout (e.g. "Professionally installed lighting" as the overlay line). (electrician/sauna-lighting site, Vancouver)
- Elevating a trust signal: move a "rated 5 stars on Google" line up into the hero itself in place of a generic "Welcome" headline, and delete the same badge/line everywhere else it repeats on the page — optionally still hyperlink it, but never style it as a prominent button, since the goal is to showcase the rating, not send traffic away to the reviews page. (electrician/sauna-lighting site, Vancouver)
- Resolving a two-CTA business (some visitors want to submit a quote form, others want to call): pick ONE primary action to visually dominate (solid button) and demote the other to a lower-contrast secondary style (outline/transparent button) — reduces "decision fatigue" by telling visitors exactly what to do first. (electrician/sauna-lighting site, Vancouver)
- Fixing inconsistent text alignment (one block centered while the rest of the page is left-aligned): pick one alignment convention and apply it throughout. (flagged independently on both the electrician site and the bookkeeping site)
- Communicating an in-person/live service that its own category name doesn't imply by default (e.g. "calligraphy" reads as static/printed): add explicit clarifying language ("on-site calligraphy" / "live calligraphy") as a pre-header/eyebrow line above the H1, rather than folding it into the H1 itself. (Belle's calligraphy site)
- Considered — as an explicit exception to her general stance against hero videos — recommending an actual hero video specifically because it would show the calligrapher's live skill in action better than any static photo, fitting this one brand's message better than the site-wide default. (Belle's calligraphy site)
- Fixing a hero image where headline text overlaps/obscures a photo the client wants preserved: shift the photo to one side of the section and move the text to the opposite side, instead of layering text directly on top of the image. (Belle's calligraphy site)
- Fixing illegible handwritten-script logo text: keep the handwritten style, but add more letter spacing and/or size — the printed portion of the same logo was already legible and didn't need the fix. (Belle's calligraphy site)
- Diagnosing a "my layout breaks differently on every screen size" complaint: the client had designed for one mid-size breakpoint (laptop, "square" aspect ratio) first, which then skewed on both desktop and mobile. Fix/process: always build for the largest screen size (desktop) first, get that right, then move down to the next size (laptop, then tablet, then phone) in sequence — never start from a mid-size breakpoint and try to make it hold in both directions. (Neri/Nancy's bookkeeping site)
- Fixing a homepage that reads as an "interior page" because it has no hero at all: add a hero section, and give it a specific, geo-targeted H1 like "[City] Bookkeeping Services" instead of the generic existing copy. (Neri/Nancy's bookkeeping site)
- Matching a headline font to an already-serif logo: switch the headline font to a serif (sourced from Google Fonts) to reinforce the same "elevated/classy" impression the logo already sends. (Neri/Nancy's bookkeeping site)
- Using Chrome DevTools as a client-safe mockup tool: explicitly clarified to the client that edits made live on-screen are local-only and don't change anything on the real site — used as a faster way to visually demo a change than rebuilding it in design software. (Neri/Nancy's bookkeeping site)

## Rules / dos & don'ts (keep every threshold, number, specific)
- Hero image target size given as a rule-of-thumb: **1400px wide × 740px tall** (glass jars site, Leanne's own stated dimensions). A second, garbled restatement of hero dimensions on Niri's site gave conflicting numbers ("1400, 1440 pixels wide," "700," then "180," then "140 by 180") — treat the clean 1400×740 figure as the reliable one.
- Glass jars site's PageSpeed Insights score at time of call, per the owner's own check: **44**.
- Product image size conflict flagged on the glass-jars site: template requires product photos uploaded at **1200×1200**, the template's own "optimized" output renders at **640×640**, and Google was separately pulling/recommending an even smaller display size, showing a **138×138** thumbnail on the homepage — three different sizes in play across homepage thumbnail, template output, and Google Shopping.
- Don't embed a live Instagram feed on the website — slows load speed, and points traffic the wrong direction (goal is Instagram → website, not the reverse). Stated as a flat recommendation. (Niri's jewelry site)
- Don't use a rotating multi-slide hero carousel — visitors scroll past before later slides ever display. Use one static hero, then stack additional themed messages as separate full sections below it. (Niri's jewelry site)
- Contrast check rule: if you removed all color and viewed the design in black-and-white, the text must still be clearly readable — a harder, more reliable bar than "do the brand colors look nice together." Automated checks (PageSpeed/accessibility-style contrast flags) can also catch this, but in Carol's specific case the automated check didn't flag a contrast problem the manual grayscale test did catch — treat the automated tool as a backstop, not a substitute for the manual check.
- Squarespace: "there's only so much control you have" over site speed on the platform — if speed is capped by the platform itself, optimize what's controllable, then shift remaining effort to the rest of SEO rather than chasing an unreachable speed number.
- Buy icons rather than use free ones. Go-to sources: **Adobe Stock** and **Creative Market**. **Shutterstock** explicitly called out as having declined in quality "lately."
- Google Fonts: free, available inside every major website builder, safe from copyright issues, and guarantees correct loading/rendering.
- Prefer real/own photography over generic stock photography, especially photos of the actual person/team doing the actual work — reduces new-visitor skepticism ("is this a scam? is this real?").
- CTA rule: only one dominant/primary action per key decision point; demote the alternate action stylistically (outline/transparent button) rather than displaying two equal-weight buttons — reduces decision fatigue.
- Keep text alignment consistent throughout a page — don't mix centered and left-aligned blocks in the same layout.
- Responsive design order: always build for the largest breakpoint (desktop) first, then work downward through each smaller size in sequence — never start from a mid-size breakpoint and try to make it hold up in both directions.
- Reduce excessive scroll-blocking animation — elements with a fixed height that catch/stick the user's scroll should be removed or de-animated, especially when competing with a CTA for attention.

- **Chrome DevTools** — used as a non-destructive, local-only way to preview design changes directly on a client's live site without editing it; described on-call as an inspection/debugging tool being repurposed for quick visual mockups instead of design software.

## Tradeoffs & nuance
- Contrast is a manual/design-eye judgment first, automated-tool check second: on Carol's site the grayscale test failed but the live automated contrast check didn't flag it — a clean PageSpeed/accessibility scan isn't proof a design is actually readable.
- Platform constrains what's fixable: Squarespace was called out twice (Carol's, Neri/Nancy's) for offering "only so much control" over speed and layout structure, versus WordPress giving more structural precision at the cost of a steeper learning curve — neither platform is framed as strictly better, just a different tradeoff of flexibility vs. guardrails.
- The "no hero video" default is explicitly broken once, for Belle's calligraphy site — because her actual service (skilled live performance) is best demonstrated in motion, the general rule bent to fit what that specific brand needed to communicate, rather than being applied uniformly.
- Trust-building sections (reviews, "family business" copy, star-rating badges) are additive right up until they're duplicated — the electrician site's 5-star badge and Niri's Google-reviews section were both kept/endorsed as good for SEO and credibility, but repeating the same trust signal in multiple spots on one page was treated as dilution, not reinforcement.
- A brand's own established equity can conflict with a color's category connotations: Niri's orange accent wasn't "wrong" in isolation, but read as mismatched against a decades-old, sophistication-coded brand — the fix wasn't "orange is bad," it was picking a color that matched that specific brand's positioning (navy/gold over energetic orange).
- CTA multiplicity mirrors real business needs (some customers want to call, others want to fill out a form), but the fix doesn't eliminate either option — it only demotes one to a visually secondary style, preserving both paths while still giving visitors one clear default action.
- Where a platform's constraints directly conflict with a client's redesign goals (Neri/Nancy's Squarespace breakpoint issues), Leanne stopped short of prescribing "switch platforms" outright, instead laying out what each option costs/gives and leaving the decision to the client.
