## Tactics & step-by-step how-to

- **Title tag / meta description audit:** open Detailed SEO (or the Hey Tony Page Audit tool) on any page — first check is whether the title tag contains the target keyword and whether a meta description exists at all. If you can't tell what the page is about from the title/meta, that's the first fix.
- **Fixing heading hierarchy on Shopify:** go to Online Store → Customize → look for "theme files," "Edit code," or "Customize theme" (naming varies by Shopify version) → open `theme.liquid` (or the relevant section file) → find the heading tag pulling the text in question → change the tag level directly in code (e.g. `<h2>` → `<h1>`).
- **Shopify Sidekick** (Shopify's built-in AI assistant in the site editor) can help guess at code-level fixes when no developer/Denroy is available.
- **CTA keyword optimization:** upgrade generic CTAs ("Shop Now," "Buy Now") to keyword-bearing versions — e.g. "Shop Treats" → "Shop Healthy Dog Treats" / "Shop Organic Dog Treats" — anchored to the page's target keyword.
- **Seed the keyword throughout page copy**, not just the H1: subheadings, "About Us" (e.g. "About Pets Gone Wild"), CTAs, section headers — repetition across the page reinforces topical relevance. Content on the page is treated as the top-priority ranking factor, ahead of backend items like schema markup, meta description, and title tags (which still must be done, just weighted lower).
- **Checking indexing status fast:** use the `site:yourdomain.com` (or `site:yourdomain.com/specific-page`) search operator in Google to see if a page is indexed at all.
- **Speeding up indexing of a stuck page:** paste the URL into Google Search Console's URL Inspection search bar. Green = already indexed. Gray with a question mark = not indexed → click **Request Indexing** (not a ranking guarantee, but tells Google to crawl and evaluate it).
- **New-site patience protocol:** if pages are crawled/found but not indexed on a 2–3-month-old site, and the sitemap was only recently submitted, give it another month or two before troubleshooting further — but in parallel, tighten internal linking (homepage → service/product/money pages; blog posts → other blog posts + priority pages).
- **Local landing-page architecture (used on Neri's bookkeeping site):** keep one hub/money page targeting the core local keyword (e.g. "bookkeeping services in [city]"). Build separate dedicated landing pages for each bottom-of-funnel, high-intent niche keyword found on that hub page (e.g. bookkeeper for HVAC companies, landscaping, pest control, pool services, plumbers, general contractors), each optimized for exactly one keyword, all internally linked from the hub via anchor text. Do not delete the hub page — it becomes the long-term internal-linking hub as more niche pages get built.
- **Local-vs-national targeting sequence:** for a business that can serve statewide/nationwide, still target the closest city first in the H1/keyword (example given: "Bookkeeper in Detroit" for a Detroit-based business), mention broader state/national service lower on the page, and only chase the broad keyword once domain authority and traffic exist.
- **Tie GBP and website targeting together:** if the website ranks for a city, the Google Business Profile tends to rank for that city too (and vice versa) — keep NAP (name/address/phone) and city targeting consistent across both.
- **Diagnosing a robots.txt/sitemap indexing block:** (1) paste robots.txt content into a checker to confirm nothing is disallowed; (2) manually click the sitemap URL listed inside robots.txt to confirm it actually loads (not a 404 or redirect); (3) if it redirects, check `.htaccess` (root of the web hosting server) and any redirect-managing WordPress plugins; (4) if unfamiliar with `.htaccess`, paste its contents into ChatGPT and ask if anything is causing a redirect.
- **Multi-location build sequencing (comedian example, 11 locations × 6 client types = up to 66 pages):** don't try to build everything at once. Priority order = home-city page + money page + blog first, then expand outward.
- **Sequencing which location pages to build next:** work backward from the cities with the **highest population**, or — better — the cities that generate the **most actual conversions/customers**. Build low-population/low-conversion cities last.
- **Multi-location menu/IA:** top-level nav item "Locations" → dropdown lists each city → hovering a city opens a second flyout with that city's service/client-type pages (e.g. "Comedian in [service] in [city]"). Homepage itself represents the business's own home city.
- **Leverage an authored book for SEO/authority:** mention it repeatedly on the site, link out to its sales listing (e.g. Amazon), and treat it as a genuine authority/E-E-A-T signal — "now that Matt has one, we know it does a lot for SEO" in terms of qualifying as an industry expert.
- **Image handling:** always use compressed **WebP** images, resized to **under 1000px** in width, unless the image is a banner.
- **Video handling:** never self-host video on any platform (Wix, WordPress, Shopify, or otherwise) — upload to YouTube, Vimeo, Daily Motion, etc., and use their embed code, so the video platform (not your server) carries the load.
- **Fixing an audience/keyword mismatch (Nicole's nanny-agency case):** go back to keyword research to confirm the correct target keyword for the *paying* audience (e.g. "find a trusted nanny" → test "hire a nanny in San Francisco" or "hire a stay-at-home nanny in San Francisco" instead of terms that read as job-seeker-facing), re-optimize the money page around it, then build supporting blog posts answering that audience's real questions (example given: "What to expect when hiring a nanny in San Francisco"), each linking back to the money page with multiple CTAs (buttons and/or anchor text) to convert blog readers into money-page visitors.
- **Heading hierarchy fix:** never let heading levels skip (found H2 → H4 with no H3) — convert the skipped-level headings up to the correct sequential level (H4s → H3s in this case).
- **No-index management in Rank Math:** go into Rank Math's page/post settings and toggle "no index" off / "allow crawlers to visit this page" on to re-enable indexing and have the page reappear in the sitemap.
- **Divi color/CSS workaround:** when Divi's built-in styling controls won't apply a color/font change, use inline CSS directly in the content, and append `!important` if Divi is still ignoring it — this is Hey Tony's own standing workaround on client sites.

## Rules / dos & don'ts (keep every threshold, number, specific)

- **One keyword per page, always.** Trying to rank one page for several keywords means it won't rank for any of them, or will rank lower for all of them.
- **Content on the page is "number one"** for SEO — ranked above backend factors like schema markup, meta description, and title tags (which are still required, just secondary).
- Every page needs a **keyword-optimized title tag** and a **meta description** — missing either is a same-day fix.
- **H1 must contain the target keyword** and must be the structurally first heading in the page's HTML, not just visually prominent (audit found a Shopify H1 sitting on a "limited time offer" element far down the page — must move to the top).
- **Never skip heading levels** (no H2 straight to H4).
- **Don't delete an existing services/hub page**, even if it feels cluttered — keep it and use it as the internal-linking hub for new niche pages.
- **Don't primary-target broad/national keywords early** if the site lacks domain authority — start hyper-local, expand later.
- **Images: WebP, under 1000px wide**, except banner images.
- **Never self-host video** — always embed from YouTube/Vimeo/Daily Motion etc.
- **Be careful with long-term no-indexing** of pages you eventually want to rank: extended no-index "backdates" a page, so when it's finally allowed to index, Google treats it as older/lower-priority than newer content (yours or competitors').
- **Google Search Console = "the number one most important tool for SEO"** — ranked above keyword-research tools and even above Google Analytics. Must be set up before making any data-driven optimization.
- **GSC and Google Business Profile are completely separate systems:** GSC covers organic website search traffic/queries (what people typed to find your site); GBP covers the Google Maps listing (calls, direction requests, and — via third-party local SEO tools — searcher distance to the business).
- **New-site crawl timing:** Google can take **2–3 weeks**, sometimes **up to ~2 months**, to resend a crawl bot to a brand-new site — don't panic before that window passes.
- **Divi CSS fallback:** inline CSS + `!important` is an accepted, standing workaround at Hey Tony for Divi's scattered styling hierarchy — not a one-off hack.
- **WordPress builders in active use at Hey Tony:** Avada (a full page builder, not just a theme), Elementor, Divi — recommendation is to pick based on personal comfort, not a single "best" answer. Avada has the deepest bench of Hey Tony-produced tutorial content (older tutorials on the Hey Tony YouTube channel, recorded by Denroy and Matt).
- **All Insiders/Hey Tony tools (including the Chrome extension) are free** — no need to purchase anything additional to do this work.

## Tradeoffs & nuance

- Marisa's full multi-location, multi-audience architecture (up to 66 pages) is the "correct" end-state structure but explicitly too much to build immediately — the guidance was to sequence realistically (home city + money page + blog first) rather than wait for a "complete" launch.
- No-indexing is a legitimate short-term tool for hiding job-board-like sections from how the site reads overall, but has a real long-term cost (backdating) — it has to be applied page-by-page with intent, not blanket-applied across a whole section, since some pages in that section (Nicole's "Work with Us") still deserve to rank.
- Deliberately under-targeting a business's true service radius (hyper-local city keyword instead of statewide/nationwide) is a conscious tradeoff: it sacrifices reach now in exchange for winnable rankings and faster domain-authority growth, with the broader keyword picked up later. Neri added a trust rationale (customers prefer visibly local providers over ones they'd need to travel to verify), which Denroy agreed with.
- Platform choice (Wix vs. WordPress) was treated as comfort-dependent rather than a technical absolute — Denroy flagged his own bias (long WordPress history) as outdated with respect to current Wix, and repeated that the "right" platform is whichever one the site owner will actually be able to maintain. WordPress's steeper learning curve is weighed against Wix's template lock-in risk (switching templates later means starting over).
- Divi's scattered, hard-to-trace styling hierarchy (many places to check for one visual property) is treated as an accepted, known pain point of that specific builder — the inline-CSS-plus-`!important` fix is a standing workaround, not a real resolution of the underlying UX problem.
- GSC vs. GBP confusion is treated as a common beginner sticking point (raised unprompted by Neri) — worth flagging proactively to new site owners rather than assuming it's understood.
- Nicole's case shows ranking well is not sufficient on its own — her site was performing (attracting applicants) but for the wrong audience, meaning SEO "success" by traffic/indexing metrics can still fail the actual business goal if the wrong keyword/audience was targeted from the start.
