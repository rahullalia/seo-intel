## Tactics & step-by-step how-to

- **Consolidating dated/annual content (CJ's "Annual Commission Update Colorado 2024" page):**
  - Create ONE new landing page with no year in the URL — this becomes the permanent money page for that topic.
  - Redirect all the old dated URLs (2024, 2025, etc.) to that single new URL.
  - Update the title tag, H1, and all in-body year references to the current year (2026).
  - Every year at renewal time, go back in and make real content changes (not just swap the digit) — e.g., cite/quote an updated official source for that year and link to it — so the page is genuinely refreshed, not just relabeled.
  - Do NOT just bolt an "this is expired, here's where to go" intro paragraph onto the old dated pages — delete/redirect them instead.
- **On-page keyword-density research process (Nary, bookkeeping niche):**
  - Google the exact target keyword (e.g., "bookkeeping services in St. Petersburg, Florida" for small-business bookkeeping) and pull up the top 3 ranking pages.
  - Don't just count the literal full keyword phrase — split it into components and count each separately: how many times does the top page use the location term ("St. Petersburg") vs. the service term ("bookkeeping" / "bookkeeping services")?
  - Feed those counts into the Rank Week keyword-count spreadsheet, then paste the spreadsheet results into GPT using the Rank Week prompt to get writing guidance.
  - Write the page copy yourself (in your own voice/expertise) — don't copy competitor wording, but match/slightly exceed their keyword usage frequency ("plus one").
  - ChatGPT or Claude can help draft, but the output must still sound like the business owner, not corporate/stiff.
- **Platform-migration URL/content preservation (Catherine, BigCommerce → Shopify):** when moving platforms, keep every ranking page's URL and content as close to identical as possible; if you can't preserve the exact URL structure, at minimum keep the content near-identical to avoid a traffic collapse.
- **Recovering from bad post-migration redirects:** don't add a second layer of redirects on top of existing ones (redirect-to-a-redirect); for pages that already lost inbound links because of the platform switch, proactively email the linking sites, tell them the URL was redirected, and ask them to update the link to point directly at the new URL.
- **Location × event-type page architecture (Maritza, comedian for HOAs/55+/corporate events across multiple FL cities):**
  - Do NOT build a page for every location-×-event-type combination (would have been ~66 pages for her).
  - Instead, build one page per location (e.g., Boca Raton) with sections/buttons for each event type (HOA, 55+, fundraiser, corporate) on that single page.
  - Run keyword research (SEMrush) to check whether people actually search a specific combo (e.g., "HOA comedian Boynton Beach"). Only build a dedicated combo page where real search volume exists — Matt estimated she'd likely find around five such combos worth their own page.
  - Link those handful of dedicated combo pages from the matching section/button on the general location page; every other button just points to the generic event-type page.
- **Building a service-area page hierarchy instead of a flat list (Jessica, Long Island NY):**
  - Don't publish one giant page that lists every single city/county as a raw link.
  - Instead: top-level page lists the main sub-regions/counties only (her case: Nassau and Suffolk — 2 counties).
  - Each county links to a dedicated page for that county, which lists its top towns (e.g., town of Hempstead).
  - Each town then gets its own page, which can list the smaller places/neighborhoods within it.
  - Net result for her: roughly 10–20 pages instead of one link-dump page.
- **Cleaning up bad Google Business Profile trust signals (David):** go through the GBP "services" list line by line and delete anything irrelevant that Google or a third party added (his profile had picked up "telemarketing" and "magazine/newsprint printing").
- **Building WordPress pages with Claude Code:** tell Claude Code which theme you're using, give it the content/info for the specific page, point it to an existing page whose layout you like as a reference, and ask it to build that page in your page builder using the supplied information — paste the resulting code into the site (expect to need some manual fixes).
- **Homepage trim-down pass (Lily, boudoir photography):** cut the image slider for one static hero; add a second prominent booking/contact CTA button further down the page (in case people miss the nav one); remove copy that doesn't help SEO or the reader ("every woman is uniquely beautiful," "boudoir is for you in the past, present, and future"); rename "Investment" to "Pricing"; remove a redundant inline inquiry form when multiple CTA buttons already exist; de-duplicate a testimonials section that appeared twice; simplify decorative side-animated buttons into three plain buttons (Portfolio / About Me / Pricing); cut a late-page "Is boudoir right for you?" persuasion section as redundant once the visitor is already deep on-site; trim the blog section to ~3 posts without an oversized background photo; remove the "Follow me on Instagram" embed.
- **Finding the real duplicate-H1 source (Keith):** don't rely on a tool's generic "too many H1s" flag — install a heading-audit browser extension that lists every H1 on the page individually; Matt found 13 H1 tags this way, including ones firing from the logo, signage graphics, and animated display elements.
- **Website speed fix sequence (AJ):** (1) audit and cut down plugins first; (2) install/configure WP Rocket; (3) run Imagify (or WP Rocket's paid image-compression add-on) to convert images to WebP; (4) only change the theme if the above doesn't get the score high enough, since a theme change forces you to rebuild the site's whole look; (5) for more advanced fixes, ask Claude Code directly how to make the site faster.
- **Async issue triage:** when a live-call fix would take too long, have the member post the specific URL/problem in the Insiders community tab so Matt can review it later instead of eating call time.

## Rules / dos & don'ts

- If content updates on a yearly cycle, never put the year in the URL — it signals to Google the page is tied to that specific year.
- Aim for roughly **800–1,000 words** on a page to rank — competitor pages Nary reviewed ranged from ~500 to ~2,500 words, so high word count is not what's driving rankings.
- Match competitor keyword usage frequency **plus one** — don't just copy wording.
- Keep URLs and content as similar as possible during any platform/website migration.
- Never redirect a redirect — always point straight to the final live URL.
- Don't build 66 (or any large combinatorial set of) location × service pages "just in case" — most won't get indexed and you can't make them meaningfully unique; build a dedicated combo page only where keyword research shows real search demand.
- Don't publish a flat list of every city/county as one page of links — "it's useless, people don't really need that." Build a region → town page hierarchy instead.
- Convert images to WebP: do it manually if you're starting fresh or have few images; use a plugin (Imagify) if the site already has hundreds/thousands of existing images.
- Never click "Apply All" on Google's recommended edits — applies to both **Google Business Profile** recommended edits/services and **Google Ads** recommended changes. A past client did this and both rankings/traffic and ad spend went sideways.
- Regularly review and delete irrelevant auto-added GBP services — treat them as bad trust signals.
- Keep WordPress plugin count to **15 or fewer**; consolidate/remove old or unused ones even if they seem harmless — they still load.
- Change the site's theme last, only after plugin cleanup and caching/image optimization haven't gotten speed high enough.
- Don't use a slider at the top of the page — it doesn't auto-advance (visitors have to know to click), and every page load has to load all slider images even if nobody sees them.
- Avoid cursive/script fonts for anything that needs to be read quickly — "any friction is friction," especially for readers (particularly younger ones) who never learned cursive.
- Call the pricing page "Pricing," not a euphemism like "Investment" — people search "[service] pricing," not "[service] investment."
- Don't duplicate the same section (e.g., testimonials) twice on one page just in case people don't scroll far — consolidate/reposition instead.
- Don't build a website directly on Claude/Claude Code as the platform — use WordPress as the base, and use Claude Code to help build individual page layouts within it.
- Claude Code has no real use on Squarespace — there isn't meaningful exposed code to work with.
- Don't publicly name or link a client's/community member's winning site, even with their explicit permission — treated as a security risk (risk of nefarious action like bad backlinks against the site once it's a known target).

## Tradeoffs & nuance

- Consolidating dated content means accepting a real, immediate hit: the old dated URL will drop out of the index and any SEO equity it had won't automatically transfer — the tradeoff is a short-term loss for a cleaner long-term structure.
- Migrating platforms after the fact is largely unrecoverable in the short term — once Catherine had already rebuilt on Shopify with new URLs, the guidance was preventive ("do it right next time"), not a way to undo the current traffic loss.
- Location × event-type page proliferation is a thin-content trap: more pages feel like more coverage, but only pages backed by actual keyword search volume are worth the dedicated build — everything else should fold into a general page instead of chasing full combinatorial coverage.
- Brand voice and SEO/conversion clarity can pull in different directions — Matt pushed to cut emotionally-branded copy ("every woman is uniquely beautiful") when it wasn't clearly serving either ranking or the reader's actual next action, even though it may be intentional brand identity.
- Community transparency has a limit: Matt is happy to use a member's real growth numbers as a teaching example but won't name/link the actual site, trading a stronger case study for protecting the member from competitive sabotage.
- Sophisticated builders still default to WordPress: even someone building a custom CMS with Claude Code (Edward Sturm) chose WordPress as the underlying platform for ease — Claude Code's usefulness is real but platform-dependent (strong on WordPress, none on Squarespace).
- Google's own automated recommendations (GBP edits, Ads suggestions) look like helpful defaults but aren't reliable — "Apply All" is framed as actively dangerous, not neutral, despite coming from the platform itself.
- Speed fixes should be sequenced from least to most disruptive: plugin cleanup, caching, and image compression are cheap and reversible; a theme change is treated as a last resort because it forces a full visual rebuild of the site.
- The Insiders' own built-in reporting tool is good enough for personal use but not yet scalable to client-facing reporting, because it's bottlenecked by a hard 100-connection cap from Google's API approval — a platform limitation outside Matt's control, prompting him to consider a separate tool entirely for that use case.
