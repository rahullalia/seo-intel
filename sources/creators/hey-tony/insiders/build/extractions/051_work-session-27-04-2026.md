## Tactics & step-by-step how-to

- Host's team sends every client a weekly "win" — process for finding one: check if ranking for more keywords, check if getting more traffic, check if one piece of content "popped off," check if ranking better for money-making terms, or log into the client's analytics and confirm actual sales. Non-analytic wins count too (e.g., a client/member solving a website problem themselves).
- Pruning bloat: pull a Search Console view of pages that aren't ranking, aren't indexed, and have no backlinks — those are the deletion candidates. Host deleted ~70 old blog posts (some dating back to 2022) this way and saw only minor traffic loss.
- Client SEO content-mapping process (used on Jennifer's 3-month client): map out the full content plan in advance — topics, which pages will internally link to which, and which topics tie to which money pages — get client sign-off on the map, then run the interview per topic.
- Efficient client interview shortcut: instead of ~10 hyper-specific questions per blog topic, write ~4 general questions that apply across most topics, then adapt the answers per post.
- Cadence that worked for a real client (no backlink work at all): 1 blog post/week + 2 city/location pages per month.
- Blog-writing workflow taught live on the call:
  1. Get a topic — via the Insiders "Blog Topic Finder" tool (under Tools), Answer the Public, or a real question a customer/lead asked you (e.g., overheard at an expo).
  2. Interview yourself in ChatGPT, answering the generated questions.
  3. Copy everything out of that ChatGPT thread, paste it into Claude, and say (paraphrased on the call): "I just did this with ChatGPT — write me the blog post using my answers." Do **not** ask ChatGPT itself to write the post — it's used only for gathering the interview answers, Claude does the writing.
- Internal linking, step by step, every time a post is published:
  1. Find 3 other existing blog posts/pages on the site relevant to the new post's topic and link to them (add a sentence/paragraph to the older post if needed to tie it in naturally).
  2. Link once to a relevant money page (product/service page) from the new post.
  3. Go back into **old, already-indexed** content and add a link forward to the brand-new post — this is what gets Google to recrawl and discover the new page fast, sometimes within an hour or two, without ever manually submitting it to Google.
  - This can be delegated: "you can definitely ask ChatGPT" to find the 3 relevant existing pages to link to (confirmed valid when a member said she does this).
- Recovering rankings after an algorithm-update drop (Kenneth's method, described as his own high-level 10-second version): take your existing page, run it head-to-head against the current top-3 ranking competitor pages for that keyword through an LLM ("through Quad" / "Gemini Close" in the transcript — almost certainly Claude and Gemini+Claude, likely an ASR mis-transcription), ask it to analyze for SEO best practices and explain why you're ranking below the top 3 with recommended changes, rewrite the page using that feedback, then let Google recrawl it — "generally within a few hours, you'll be often in the top three."
- Keyword-gap triage via Google Search Console: open Search Console → Search Results → Pages tab → pick a money page → check its queries and average position. Branded terms (your own business name) will already rank fine — ignore those. Find the non-branded/local terms ranking poorly and target those for fresh keyword research/content work. (Demoed live on host's own "Search Engine Optimization" money page: "Hey Tony SEO" ranks branded/fine; "SEO Hamilton" was ranking poorly and flagged as a target.)
- Long-tail keyword seeding: don't chase SEO-plugin keyword-density scoring for long-tail/question content. Just answer the full question naturally — the underlying phrase will end up repeated roughly 3–4 times on its own (title tag, H1 tag, meta description, once in the body copy) without deliberate stuffing.
- Topical authority for a new/small-market site: if your city is too small to rank on its own, target state-level keywords first, then build individual location pages for the top 10 highest-population cities in that state. You don't need to build out a full hub/pillar structure to reference location — a brief mention plus a link at the bottom of an otherwise-generic blog post (e.g., "if you're looking for website design in West Virginia" → link to a "Website Design WV" money page) is enough.
- Building custom on-domain pages/tools with Claude Code: describe your CMS/page builder/theme to Claude Code and ask it to build the page in that same builder/theme so you can copy-paste the resulting code straight into your native editor — keeps the page hosted on your own domain instead of on an external app/builder.
- Full WordPress/Avada reset when a template switch leaves orphaned pages and a blank live site (walked live with Marita):
  1. Check the live URL — remove any `/wp` in the path; also confirm the site has actually been published.
  2. Clear browser cache (already ruled out in this case).
  3. In wp-admin → Pages, find the page set as the front page/homepage.
  4. Click "View" (not Edit) next to Trash on that entry to see what's actually live.
  5. If blank, go back into the page editor, open the first section/element (e.g., the "hero") to confirm content genuinely exists in the builder.
  6. Right-click the live page → View Page Source to check whether there's any real HTML there at all.
  7. If the source is empty, don't patch it — do a full clean reinstall: Softaculous → Uninstall (this removes WordPress entirely, not just the Avada theme) → confirm → Remove Installation.
  8. Return to WordPress management → Install a new copy (again verify no `/wp` in the path).
  9. Go through the fresh install: set a new admin password, change the admin username away from the default "admin," then reinstall Avada from scratch.
  10. If the installer throws "the following errors were found... files already exist in the target folder" (index.php, .htaccess): either delete those leftover files first, or check the box to override/select another folder.
  11. Stop screen-sharing before typing or saving the new admin password.
- Untested idea floated for replicating the LinkGap signal-effect on a local business (host's own caveat: "I don't know if it's the exact way, but..."): get friends/family/community members to manually Google a target term, scroll down, find your site, click through, and fill out the contact form — to manually manufacture the branded-search + click-through + conversion pattern and see if it moves local rankings.

## Rules / dos & don'ts (keep every threshold, number, specific)

- Keep landing pages hosted on your own website/domain, always — don't host them on an external builder (a member had used something like Netlify). An externally-hosted page can still be useful for people to contact/hire you, but it likely won't rank.
- If you do use an external redirect page, still link back to your own homepage from it — that counts as external traffic.
- Put your pricing/cost ranges on your website even if you're a boutique/premium provider — "if you don't have any prices on your website, you're getting left out entirely" from price-shoppers.
- Content cadence that got a real client "at capacity": 1 blog post/week + 2 location pages/month, with zero backlink work.
- Client interview length: ~4 general questions per topic is enough — don't need ~10 highly specific ones.
- Keyword definitions: short-tail keyword = 3 words or fewer; long-tail keyword = a full question.
- Ignore Rank Math/Yoast's short-tail keyword-density restrictions when writing long-tail/question-based posts — those plugins are "geared towards like three or four words," which works against full-question content.
- Internal linking rule for every new post: 3 links to other relevant existing posts/pages + 1 link to a money page (adjustable if you genuinely don't have 3 relevant posts yet, e.g. your very first post).
- Always add a link from old, already-indexed content forward to a brand-new post right after publishing — don't rely on Google finding it unassisted.
- Only delete old pages if GSC shows no ranking, no indexing, AND no backlinks — and even then, be cautious: "I don't recommend deleting 70 pages from your website necessarily."
- Exact-keyword domain matching "appears to have dropped in the last two Google algorithm updates" — having the target keyword literally in your domain no longer reliably helps rankings.
- Change the WordPress admin username away from the default "admin" during any fresh install.
- 15% of the roughly 2 billion Google searches per day are brand-new/never-searched-before — rank-tracking tools (Moz, SEMrush, etc.) can only ever show the keywords they've detected you ranking for, never the full universe, so a low keyword count in these tools isn't necessarily bad news.
- Host's stated stance (his own opinion, not universal doctrine): skip content hubs/pillar-and-spoke structures — just write blog posts that directly answer real questions.

## Tradeoffs & nuance

- Bulk-deleting stale pages worked for the host (minimal traffic loss) but he explicitly cautions against copying it blindly — screen for zero ranking + zero indexing + zero backlinks first, and treat large-scale deletion carefully regardless.
- The LinkGap.io result is explicitly flagged by the host as an outlier he can't fully generalize: "I'm in a different situation than a lot of you where I can push a lot of people to a website" — his large existing audience did the heavy lifting, and he's still working out how (or whether) the same conversion-signal effect could be manufactured for a small local business.
- An externally-hosted landing page (off your own domain) can still generate leads/conversions, but the tradeoff is it likely won't rank — host's rule of thumb is to keep pages on your own domain whenever ranking matters, reserving external hosting for one-off, non-ranking-dependent use cases.
- Rank Math/Yoast's built-in keyword-density guidance (tuned for 3–4 word short-tail phrases) actively conflicts with writing long-tail/question-based posts — the host's advice is to disregard the plugin's scoring pressure in that case rather than force short-tail phrasing into long-form answers.
- The anti-content-hub, anti-pillar-content stance is presented as the host's own opinion/bias against how "SEO people" frame things, not a neutral consensus — offered as a simpler alternative to Greg's hub-and-spoke plan rather than a proven refutation of it.
- Checklists are useful references but shouldn't be applied rigidly — e.g., a brand-new site's very first blog post has no older posts to internally link to yet, and that's fine; the internal-linking rule is meant to be applied as content volume allows, not forced on day one.
- The Google Business Profile visibility gap (ranking for some keyword+radius combinations but not others at distance) is left unresolved — host's only offered explanation is "might be more competitive," not a diagnosed fix.
- Whether to mention location terms (city/state) inside blog posts is a balancing act: too much risks competing with/diluting dedicated money pages; the host's resolution is a light touch — a brief mention plus a link at the bottom of the post rather than either avoiding the location entirely or building it out into full location-specific blog content.
